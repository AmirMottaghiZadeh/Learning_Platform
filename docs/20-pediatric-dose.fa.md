# تنظیم دوز اطفال — طرح مرحله‌ای منتخب

نام رابط **تنظیم دوز اطفال / Pediatric Dose Adjustment** است. کاربر طرح ۲ را از [سه پیش‌نمایش](designs/pediatric-dose/README.md) انتخاب کرد. قابلیت اکنون در کد اپ پیاده‌سازی شده است؛ انتشار سرور و نسخهٔ اپ مرحله‌ای جدا است.

## جایگاه و جریان رابط

خانه ← ماشین‌حساب‌های بالینی ← کودکان / Pediatrics ← بخش مستقل تنظیم دوز اطفال. این ورودی در جست‌وجوی عمومی ماشین‌حساب‌ها هم دیده می‌شود. Snapshot فعلی ۴۸۳ ماشین‌حساب دارد؛ اپ این ابزار را به آن‌ها اضافه می‌کند و تعداد نمایشی ۴۸۴ می‌شود. API فهرست Medscape و جدول‌های موجود دست‌نخورده‌اند؛ هیچ شناسهٔ محلی Pediatrics در مسیر ثابت فرض نشده است.

1. **کودک:** سن با واحد روز/ماه/سال، وزن به کیلوگرم؛ همهٔ ورودی‌ها ابتدا خالی‌اند. ارقام فارسی، عربی و ممیز محلی پذیرفته می‌شوند. دامنهٔ ورودی با اعتبارسنج موتور منبع بررسی می‌شود.
2. **دارو:** جست‌وجوی نام فارسی/انگلیسی؛ انتخاب صریح دارو، اندیکاسیون، قدرت/فرآورده و در صورت چندگزینه‌ای بودن، فاصلهٔ مصرف. در رژیم وابسته به GA/PMA، سن حاملگی هنگام تولد آشکار و الزامی است و مقدار خالی به ۴۰ هفته تبدیل نمی‌شود.
3. **نتیجه:** مقدار هر نوبت فرآورده، معادل دارویی، دفعات، مجموع روزانه، سقف‌ها، مدت، راه مصرف، جمعیت منبع، هشدارها و نقل‌قول. رژیم چندمرحله‌ای همهٔ مراحل منبع را نگه می‌دارد؛ گزینه‌های فرآوردهٔ ترکیبی به هم ادغام نمی‌شوند. عنوان «گزینه‌ها / مراحل منبع» به معنی تجویز هم‌زمان همهٔ گزینه‌ها نیست؛ برنامه‌ها و یادداشت منبع همان‌جا نمایش داده می‌شوند.

فرآوردهٔ `ok: false` مقدار حجم/تعداد پیشنهادی نمی‌گیرد. در صورت قابل‌محاسبه بودن دوز دارو، همان دوز با پیام نیاز به فرآورده یا ابزار مناسب نمایش داده می‌شود. سقف دوز، حداکثر دفعات و برنامهٔ روزهای مصرف از خروجی موتور گرفته می‌شوند و منطق تازه‌ای برای گردکردن دوز در رابط وجود ندارد.

«بیمار جدید» ورودی و انتخاب‌های قبلی را پاک می‌کند. برگشت میان مراحل، کاربر را برای اصلاح انتخاب‌ها برمی‌گرداند. باز کردن متن منبع از نتیجه به خوانندهٔ فعلی UpToDate متصل است؛ برگشت از مقاله، وضعیت مرورشده را از حافظهٔ ناوبری بازیابی می‌کند.

## فایل‌ها و API

| فایل | مسئولیت |
|---|---|
| `frontend/src/screens/PediatricDoseScreen.tsx` | جریان سه‌مرحله‌ای با اجزای React Native، رنگ و فونت اپ |
| `frontend/src/components/calculator/PediatricChoice.tsx` | انتخاب‌گر بومی/وب برای رژیم و فرآورده |
| `frontend/src/components/calculator/PediatricResult.tsx` | نتیجه، محدودیت‌ها و متن پشتوانه |
| `frontend/src/pediatricDose/catalog.ts` | افزودن ورودی مستقل به دامنهٔ واقعی Pediatrics؛ fallback برای snapshot خالی |
| `frontend/src/pediatricDose/model.ts` | تبدیل ورودی، اعتبارسنجی، انتخاب خروجی بدون حذف مراحل و قالب عدد |
| `frontend/src/pediatricDose/engine.js` | کپی بدون تغییر موتور منبع کاربر |
| `frontend/src/pediatricDose/version.ts` | شناسهٔ SHA-256 موتور مورد انتظار کلاینت |
| `backend/apps/calculators/pediatric.py` | API احرازشده و کنترل ویژگی/سهمیهٔ `calculators` |
| `backend/apps/calculators/data/pediatric-dose.json` | ۵۰ مدخل و ۲۳۳ رژیم با فرآورده، شرط، سقف و نقل‌قول اصلی |
| `frontend/src/pediatricDose/provenance.json` | مسیر و هش فایل‌های منبع هنگام انتقال |

`GET /api/v1/calculators/pediatric-dose/` پاسخ `{schema_version: 1, engine_sha256, source, drugs}` می‌دهد. مسیر اختصاصی پیش از مسیر عمومی `calculators/{slug}/` قرار گرفته است. مدل جدید یا migration پایگاه داده لازم نیست.

API به ورود نیاز دارد و همان مجوز ماشین‌حساب‌ها را اعمال می‌کند؛ باز کردن ابزار یک استفاده از `calculators` با کلید `pediatric-dose` محسوب می‌شود. باز کردن دوبارهٔ همان ابزار در همان دوره دوباره سهمیه کم نمی‌کند. دریافت داده نیازمند اتصال است؛ پس از دریافت، محاسبهٔ ورودی‌ها روی دستگاه است. مجموعه در کش پایدار TanStack Query ذخیره نمی‌شود.

## منبع و همگام‌سازی

منبع کاربر: `/home/amir/Documents/Medscape/peds_dose/`. تمام تعریف‌های دارو بدون تغییر مقادیر و شرایط کپی شده‌اند؛ بایت‌های موتور با هش منبع برابرند. نام فارسی دارو لایهٔ نمایش است. نقل‌قول‌ها، اندیکاسیون‌ها و یادداشت‌های بالینی مطابق مجموعهٔ منبع باقی می‌مانند و بازترجمهٔ خودکار نشده‌اند.

از پوشهٔ `frontend/`:

```bash
node scripts/sync-pediatric-dose.mjs --check
node scripts/sync-pediatric-dose.mjs --source /home/amir/Documents/Medscape/peds_dose
npm run test:pediatric-dose
npm run typecheck
npm run build:web
```

فرمان اول فقط تطبیق منبع را بررسی می‌کند. فرمان دوم داده، موتور، شناسهٔ نسخه و provenance را به‌روزرسانی می‌کند؛ مسیر منبع بیرون از پروژه را تغییر نمی‌دهد. تغییر منطق موتور باید همراه با بازبینی/به‌روزرسانی تست‌های انتقال‌یافته از منبع باشد. تست‌های بالینی اولیه در `frontend/scripts/pediatric-dose/engine.test.cjs` و `regressions.test.cjs` هستند؛ فقط مسیر بارگذاری fixture آن‌ها تغییر کرده است.

بک‌اند و اپ با هم منتشر شوند. API داده را در حافظهٔ فرآیند نگه می‌دارد؛ پس از به‌روزرسانی snapshot، فرآیند بک‌اند باید دوباره شروع شود. اگر SHA-256 موتور کلاینت با مجموعهٔ سرور تطبیق نکند یا نسخهٔ ساختار پشتیبانی نشود، رابط محاسبه را متوقف و نیاز به به‌روزرسانی را نشان می‌دهد؛ دادهٔ موتور ناسازگار اجرا نمی‌شود.

این ابزار تنظیم دوز بر اساس سن، وزن و اندیکاسیون است. تنظیم دوز کلیوی/کبدی در موتور منبع وجود ندارد و در گام اول به کاربر گفته می‌شود. تاریخ انتقال یا ساخت، تاریخ بازبینی آخرین نسخهٔ آنلاین مونوگراف پزشکی نیست؛ محدودیت‌های باقی‌ماندهٔ مجموعهٔ منبع دربارهٔ بازبینی بالینی و تأیید قدرت فرآورده‌ها همچنان برقرارند.

## حریم ورودی و بررسی

سن، وزن و GA در state صفحه هستند؛ به API، AsyncStorage یا کش query ارسال/نوشته نمی‌شوند. برای بازگشت از مقاله فقط یک snapshot در حافظهٔ ناوبری همان حساب نگه داشته می‌شود؛ state مرورگر فقط علامت برگشت عمومی دارد. «بیمار جدید» snapshot مسیر جاری را هم پاک می‌کند. ثبت فعالیت فقط بخش و مختصات/زمان را مطابق سازوکار فعلی اپ می‌گیرد.

تست‌ها شامل ۴۲ رگرسیون اصلی موتور/داده، تست‌های کاتالوگ مستقل، ارقام فارسی، انتخاب صریح، حفظ مراحل و ناسازگاری نسخه؛ API ورود/پلن/سهمیه؛ و بررسی مرورگر از دامنهٔ Pediatrics تا خروجی و منبع هستند. بررسی منبعِ این انتقال ۲۴۷ نقل‌قول را در دیتابیس محلی پیدا کرد، با صفر ناموجود و صفر خطا. این تطبیق جای بازبینی بالینی مستقل را نمی‌گیرد.

نتیجهٔ بررسی این پیاده‌سازی: ۵۱ تست موتور/رگرسیون و اتصال فرانت‌اند، ۴۲ تست مرتبط بک‌اند شامل OpenAPI، TypeScript، خروجی وب و باندل Hermes اندروید موفق بودند. در مرورگر مسیر کامل با کاتالوگ ۴۸۳تایی، ورودی فارسی، GA اجباری، حجم غیرقابل‌اندازه‌گیری، برگشت از منبع، پاک‌کردن بیمار و نماهای ۳۷۵/۷۶۸/۱۴۴۰ بررسی شد. قالب‌های Card و سایهٔ قاب از توکن‌های موجود اپ حفظ شده‌اند. [تصویر نتیجهٔ واقعی](designs/pediatric-dose/screenshots/implemented-result.jpg).

مرحلهٔ frontend در CI نیز `npm run test:pediatric-dose` را پیش از خروجی وب اجرا می‌کند؛ تست‌های بالینی به مسیر منبع روی لپ‌تاپ وابسته نیستند.
