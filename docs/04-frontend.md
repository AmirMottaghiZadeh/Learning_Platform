# ۴. اپ (Expo — اندروید، iOS و وب)

کد اپ در `frontend/` است. همین کد سه خروجی دارد: اپ اندروید، اپ iOS، و وب‌اپ (PWA) که روی `app.pharmenta.ir` سرو می‌شود.

## ساختار `frontend/src/`

| پوشه | محتوا |
|---|---|
| `api/` | `client.ts` (axios، تمدید خودکار توکن)، `endpoints.ts` (فراخوانی‌های دامنه)، `support.ts` (چت و اعلان)، `device.ts` (شناسه و مشخصات نصب)، `types.ts` (شکل پاسخ‌ها)، `queryClient.ts` (TanStack Query و ذخیرهٔ کش روی دستگاه) |
| `store/` | zustand: `auth.ts` (وضعیت ورود)، `nav.ts` (ناوبری)، `session.ts` (ذخیرهٔ توکن‌ها)، `reader.ts` (تنظیمات خواندن مقاله)، `library.ts` (علاقه‌مندی‌ها و هایلایت‌ها) |
| `navigation/` | `Navigator.tsx` (دروازهٔ ورود و نمایش صفحه)، `types.ts` (کلید صفحه‌ها و تب‌ها)، `back.ts` (دکمهٔ «برگشت» یکپارچه) |
| `screens/` | هر صفحه یک فایل؛ ۳۳ صفحه در ساختار بررسی‌شدهٔ ۲۰۲۶-۱۱-۰۷، شامل `SupportScreen`، `DevicesScreen` و `NotificationsScreen` |
| `components/` | اجزای مشترک: `primitives/` (متن، کارت، دکمه، ورودی، آیکون...)، `calculator/`، `article/`، `offline/`، `plan/` (بخش برنامهٔ خانه و انتخاب‌گرهای برنامه)، `AppShell`، `BottomNav`، `ScreenChrome` |
| `offline/` | دانلود، رمزگشایی و خواندن بسته‌های آفلاین، و Service Worker |
| `activity/` | صف رویداد حساب، زمان پیش‌زمینه و ثبت لمس/کلیک ریشه و مقاله |
| `notifications/` | ثبت اشتراک Expo اندروید و Web Push، مجوز کاربر و باز کردن گفت‌وگو از اعلان |
| `pwa/` | تشخیص امکان نصب وب‌اپ، رویداد نصب و راهنمای نصب با نسخهٔ وب و بومی |
| `tour/` | تور راهنمای هر بخش: `TourContext.tsx`، `TourOverlay.tsx`، `tours.ts` (مرحله‌ها)، `previews.tsx` (پیش‌نمایش‌های متحرک) |
| `i18n/` | `strings.ts` (همهٔ متن‌های رابط، فارسی و انگلیسی) و `LanguageProvider.tsx` |
| `theme/` | `tokens.ts` (رنگ، فاصله، گوشه، سایه)، `ThemeProvider.tsx` (روشن/تیره)، `fonts.ts` (وزیرمتن) |
| `utils/` | موتور ماشین‌حساب، تبدیل HTML مقاله‌ها، تاریخ شمسی، شدت تداخل و... |
| `hooks/` | `useDebounced` |

مسیر `@/` به `frontend/src/` اشاره می‌کند (`paths` در `tsconfig.json`؛ Metro در Expo همین را خودش اعمال می‌کند).

زنجیرهٔ صفحه ← منبع داده ← API/بستهٔ محلی و فایل‌های متناظر سرور در [16-code-flows.md](16-code-flows.md) آمده است.

## شروع اپ

`App.tsx` به این ترتیب کار می‌کند:

1. `registerServiceWorker()` فقط در وب و فقط در بیلد production، `sw.js` را ثبت می‌کند؛ `initializeInstall()` از `pwa/install` هم مدیریت رویداد نصب وب‌اپ را آماده می‌کند.
2. Providerها: SafeArea ← تم ← زبان ← `PersistQueryClientProvider`.
3. `Gate` فونت، تم و زبان را آماده می‌کند، `useAuth.hydrate()` را صدا می‌زند و `useOfflineBoot()` بسته‌های آفلاین را بررسی می‌کند.
4. `Navigator` بسته به وضعیت حساب یکی از این‌ها را نشان می‌دهد:
   - در حال بارگذاری
   - `AuthScreen` (بیرون از حساب): اول در حالت **ثبت‌نام** باز می‌شود. پیوند «قبلاً ثبت‌نام کردی؟ وارد شو» زیر فرم درشت است تا دیده شود. دکمهٔ برگشت از ورود به ثبت‌نام برمی‌گردد.
   - `SetPasswordScreen` (ورود با کد پیامکی و هنوز بدون رمز)
   - `OnboardingScreen` (پروفایل تکمیل‌نشده)
   - اپ اصلی با نوار پایین
5. اپ اصلی داخل `TourProvider` است و `TourOverlay` (تور راهنما) روی آن می‌نشیند. شرح در [تور راهنما](#تور-راهنما-srctour).
6. `UpdatePrompt` روی همه‌چیز می‌نشیند:
   - **روی گوشی** (`components/UpdatePrompt.tsx`): اگر نسخهٔ تازه‌تری اعلام شده باشد، پیشنهاد به‌روزرسانی یا صفحهٔ به‌روزرسانی اجباری را نشان می‌دهد.
   - **در وب** (`UpdatePrompt.web.tsx`): بعد از هر دیپلوی، نوار «بارگذاری دوباره» را نشان می‌دهد.

   شرح کامل در [08-deployment.md](08-deployment.md#پیام-به‌روزرسانی-داخل-اپ).

## آنبوردینگ و برنامهٔ مطالعه

**آنبوردینگ** (`OnboardingScreen`) پنج قدم دارد:

1. رشته
2. هدف
3. سطح
4. **برنامه:**
   - تاریخ آزمون (به‌جز برای «مرور بالینی روزانه»)
   - دسته‌های درس این ترم (فقط برای «امتحانات ترم»)
   - دقیقه‌های روزانه
   - روزهای مطالعه
5. **خلاصه:** برنامهٔ ساخته‌شده و پیشنهادهای شروعِ هر رشته

سرور از این پاسخ‌ها برنامهٔ مطالعه را می‌سازد ([05-api.md](05-api.md#برنامهٔ-ساخته‌شده-از-آنبوردینگ)).

**بخش برنامهٔ خانه** (`components/plan/PlanSection.tsx`) زیر کاشی‌های «درِ ورودی مسیرها» است و ظاهر بقیهٔ خانه را تغییر نمی‌دهد:

- **سرِ بخش:** روزهای مانده تا آزمون، «هفتهٔ ۲ از ۶» و درصد پیشرفت برنامه. در مرور روزانه، فقط دقیقه‌های روزانه.
- **«کارهای امروز»:** هر کار با زمانش.
  - دایرهٔ کنار هر کار آن را انجام‌شده می‌کند.
  - لمس خود کار، دارونامه یا آزمون یا مرور اشتباه‌هایش را باز می‌کند.
  - دکمهٔ پایین، کار بعدی را شروع می‌کند.
- **«این هفته»:** شنبه تا جمعه، با این حالت‌ها برای هر روز:
  - انجام‌شده
  - امروز
  - جامانده
  - روز مطالعه
  - آزاد

داده از `GET /me/plan/today/?brief=1` می‌آید و هر بار که خانه باز می‌شود دوباره گرفته می‌شود. بدون برنامه، کارتی برای ساختن برنامه دیده می‌شود. اگر پلن کاربر برنامه‌ریزی (`stats`) را نداشته باشد، همان کارت قدیمی «فصل بعدی تو» نشان داده می‌شود.

**ویرایش برنامه** (`PlanningSetupScreen`) برای تاریخ آزمون همان انتخاب‌گر آنبوردینگ را دارد (`components/plan/PlanPickers.tsx`): «۱، ۲، ۳ یا ۶ ماه دیگر» یا تاریخ دقیق، شمسی در فارسی.

عنوان رابط این بخش «دارونامه» / `Formulary` است. نام دارو در فارسی `name_fa` و در انگلیسی `name` است؛ نبود ترجمه به نام انگلیسی برمی‌گردد. کلید مسیر `lessons` حفظ شده است.

برچسب کلی دارو از `is_reviewed` در API می‌آید: `DrugReviewBadge` تیک سبز «بازبینی شده» یا هشدار قرمز «بازبینی نشده» را در فهرست، جست‌وجو و جزئیات نشان می‌دهد؛ این وضعیت با خوانده شدن دارو توسط کاربر مستقل است. در هر بخش جزئیات، `other_sources_fa/en` فقط در صورت داشتن متن زیر عنوان «اطلاعات سایر منابع» نمایش داده می‌شود و در جست‌وجوی داخل دارو و زمان مطالعه هم حساب می‌شود. اگر متن خالی باشد هیچ عنوان یا کادر اضافه‌ای ساخته نمی‌شود. خلاصه یا اطلاعات تکمیلیِ تک‌زبانه به زبان دیگر برمی‌گردند.

پاسخ‌های `chapter` و `lesson-drug` هنگام هر باز شدن، با حفظ نمایش فوری کش، دوباره دریافت می‌شوند تا وضعیت بازبینی و اصلاح‌های مدیریت به‌روز شوند. نسخهٔ کش `2026-11-08-drug-review-sources` پاسخ‌های قدیمی فاقد فیلد جدید را کنار می‌گذارد.

**فهرست داروهای یک فصل** (`LessonListScreen`): هر گروه ATC سطح ۴ یک نوار به رنگ اصلی اپ دارد، با نام سفید، کد و تعداد داروها، و داروهایش زیر آن در یک کارت یکپارچه می‌آیند. نوار هنگام پیمایش بالای صفحه می‌چسبد.

## آزمون با دسته و زیردسته

ورودی آزمون در «خانه ← آموزش ← آزمون» باقی است. `QuizScreen` اجرای سؤال و نتیجه را مدیریت می‌کند؛ `components/quiz/QuizSetup.tsx` مرورگر انتخاب موضوع است:

1. شبکهٔ دسته‌های دارویی، با همان کارت‌ها و آیکون‌های مرورگر فلش‌کارت قبلی.
2. فهرست زیردسته‌های همان دسته، با نام دوزبانه و تسلط حاصل از آزمون‌های قبلی.
3. انتخاب فصل اختیاری ATC، تعداد ۵/۱۰/۱۵/۲۰ سؤال و شروع آزمون؛ پیش‌نمایش از API تعداد سؤال‌های موجود را نشان می‌دهد و در نبود سؤال کافی شروع غیرفعال است.

منبع دسته‌بندی `lessonsApi.groups` و `groupByCategory` است. جست‌وجو، خطای دریافت/تلاش دوباره و برگشت مرحله‌ای پشتیبانی می‌شوند. برنامهٔ مطالعه موضوع را با `navigate("quiz", { topic })` می‌فرستد؛ خودآزمایی یک دارو همچنان با `ingredientSlug` مستقیم وارد سؤال‌ها می‌شود. بخش فلش‌کارت، جعبهٔ لایتنر و سوابق مربوطه حذف شده‌اند؛ [شرح مهاجرت](19-quiz-navigation-and-flashcard-removal.fa.md).

## تنظیم دوز اطفال

طرح مرحله‌ای منتخب کاربر در `PediatricDoseScreen.tsx` است: مشخصات کودک ← انتخاب دارو، اندیکاسیون، فرآورده و فاصلهٔ مصرف ← نتیجه و متن پشتوانه. `includePediatricDose` آن را به شکل ورودی مستقل داخل Pediatrics، کنار ماشین‌حساب‌های موجود و در جست‌وجوی عمومی اضافه می‌کند؛ شناسهٔ محلی دامنه ثابت نیست و دادهٔ Medscape تغییر نمی‌کند.

موتور مستقل در `src/pediatricDose/engine.js` است. داده از API محافظت‌شده دریافت و محاسبه روی دستگاه انجام می‌شود. ورودی‌ها پیش‌فرض خالی‌اند و به سرور یا ذخیره‌ساز پایدار نمی‌روند. نسخهٔ داده باید با SHA-256 موتور تطبیق کند. منبع در خوانندهٔ فعلی UpToDate باز می‌شود؛ برگشت به نتیجه، اطلاعات مرورشده را از حافظهٔ ناوبری بازیابی می‌کند. [جزئیات قابلیت و محدودیت‌ها](20-pediatric-dose.fa.md).

## اعلانات اپ

پیام‌های مدیر (`GET /announcements/`، [05-api.md](05-api.md)) روی خانه، بالای کارت UpToDate. کد: `components/announcements/`.

- **کارت (`AnnouncementCard`):** برچسب نوع با آیکون، عنوان، متن، دکمه و ×. اگر اعلان بسته‌شدنی نباشد، × ندارد. با چند اعلان، «۱ از ۳» و دکمه‌های قبلی و بعدی دارد.
- **اولین بار (`AnnouncementBox`):** اعلانی که کاربر هنوز ندیده، با `Modal` باز می‌شود و پشتش تیره است تا فقط کارت دیده شود.
  - **«بعداً»، دکمهٔ برگشت یا زدن روی سایه:** سایه را برمی‌دارد و کارت بالای خانه می‌ماند.
  - **ترتیب با تور:** اگر تور خانه در حال پخش یا هنوز دیده‌نشده باشد، تا پایانش صبر می‌کند.
- **بستن:** × یا زدن دکمهٔ معمولی، اعلان را برای همیشه می‌بندد (`dismiss`). برای اعلان نصب، حذف محلی به تفکیک شناسهٔ حساب هم نگهداری و در صورت قطع ارتباط، پس از دریافت دوبارهٔ فهرست با سرور همگام می‌شود.
- **اعلان نصب:** دو دکمهٔ «نصب» و «دیگر نشان نده» دارد. `pwa/install.web.ts` از شروع اپ رویداد `beforeinstallprompt` را نگه می‌دارد و با کلیک کاربر، پنجرهٔ تأیید مرورگر را باز می‌کند. انصراف از پنجره یا زدن نصب، اعلان را دائماً نمی‌بندد. `appinstalled` یا اجرای standalone آن را پنهان می‌کند؛ نصب مشاهده‌شده در همین مرورگر هم محلی نگهداری می‌شود. در Safari/iOS راهنمای Share → Add to Home Screen → Add نمایش داده می‌شود؛ نصب بی‌تأیید کاربر ممکن نیست. تشخیص نصب در مرورگرها محدود است؛ به‌ویژه Safari نمی‌تواند نصب قبلی در دستگاه دیگر یا محیطی جداگانه را گزارش کند. «دیگر نشان نده» مستقل از این تشخیص، روی حساب ذخیره می‌شود. پیاده‌سازی بومی (`pwa/install.ts`) اعلان نصب وب را حذف می‌کند.
- **رویدادها:** هر اعلانی که روی صفحه می‌آید `seen` ثبت می‌شود؛ زدن دکمه `click`.
- **مقصد دکمه (`links.ts`):** نشانی وب با `Linking.openURL` باز می‌شود و بخش‌های اپ با `navigate` یا `setTab`. مقصدی که اپ نمی‌شناسد کاری نمی‌کند.
- **تازه شدن:** کش ۵ دقیقه است و کشیدن صفحهٔ خانه به پایین، فهرست را هم تازه می‌کند.

## تور راهنما (`src/tour/`)

هر بخش یک تور کوتاه دارد: خانه، دارونامه، فهرست داروهای یک دسته، آزمون، ماشین‌حساب، گایدلاین، بیماری‌ها، UpToDate و LexiComp.

- **کی پخش می‌شود:** بار اول که کاربر وارد آن بخش می‌شود، خودکار پخش می‌شود. تور خانه درست بعد از آنبوردینگ پخش می‌شود. تورهای دیده‌شده روی دستگاه ذخیره می‌شوند (AsyncStorage، کلید `pharmexa.toursSeen.v1`).
- **دکمهٔ «?»:** در سرتیتر هر بخش، تور را دوباره پخش می‌کند. این دکمه جای برگهٔ راهنمای متنی قدیم (`HelpSheet`) را گرفته است. صفحه‌هایی که تور ندارند، مثل اجرای آزمون و نتیجه‌اش، هنوز همان برگه را دارند.
- **هر مرحله:**
  - حلقه‌ای دور یک بخش واقعی صفحه می‌کشد. حلقه از یک بخش به بخش بعد سر می‌خورد و اگر آن بخش بیرون از صفحه باشد، صفحه تا آن اسکرول می‌شود.
  - کارتی با یک پیش‌نمایش متحرک کوچک، یک عنوان و یک خط متن نشان می‌دهد.
  - مرحله‌ای که بخش مشخصی ندارد، کارت را وسط صفحه نشان می‌دهد.
- **رفتار کارت:**
  - کارت زیر یا بالای بخش می‌نشیند. اگر بخش از صفحه بلندتر باشد، پایین صفحه می‌نشیند.
  - نوارهای بالای کارت مثل استوری پر می‌شوند و تور هر ۵٫۵ ثانیه خودش جلو می‌رود.
  - لمس پیش‌نمایش تور را نگه می‌دارد.
  - «رد شدن» یا دکمهٔ برگشت تور را تمام می‌کنند.
  - تا وقتی تور پخش می‌شود، لمس صفحهٔ زیرش کار نمی‌کند.

برای افزودن تور به یک صفحه:

1. مرحله‌ها را در `TOURS` در `tours.ts` بنویسید. هر مرحله متن فارسی و انگلیسی، یک پیش‌نمایش (`PreviewSpec`) و یک `target` اختیاری دارد.
2. بخش‌های صفحه را با `<TourTarget id="...">` بپیچید.
3. `useTour(key, ready)` را صدا بزنید. `ready` باید وقتی درست شود که محتوای صفحه رسیده باشد. این قلاب را قبل از هر `return` زودهنگام بگذارید.
4. به `ScreenChrome` پراپ `tour={key}` بدهید تا دکمهٔ «?» پیدا شود. در سرتیترهای سفارشی از `TourButton` استفاده کنید.

`Screen` با `TourScrollContext` به تور می‌گوید چطور اسکرول کند. `OfflineDownloadButton` پراپ `tourId` دارد، چون اگر بسته منتشر نشده باشد، خودش پنهان می‌شود.

## ناوبری

اپ روتر ندارد. ناوبری یک ماشین حالت ساده در `store/nav.ts` است:

- `navigate(screen, params)` صفحه را به تاریخچه اضافه می‌کند. `goBack()` یک قدم برمی‌گردد. `setTab(tab)` تب پایین را عوض و تاریخچه را پاک می‌کند. `reset(screen)` هم وجود دارد.
- تب‌ها: `dashboard`، `lessons`، `profile` (`TAB_ORDER`).
- کلید همهٔ صفحه‌ها در `navigation/types.ts` (`ScreenKey`) است و نگاشت کلید به کامپوننت در `CurrentScreen` در `Navigator.tsx`.
- دکمهٔ برگشت اندروید و دکمهٔ برگشت مرورگر هر دو از `navigation/back.ts` می‌گذرند. ترتیب برگشت:
  1. اگر صفحه سطح داخلی دارد (مثلاً دستهٔ آزمون ← زیردسته ← تنظیم آزمون)، اول از آن سطح‌ها برمی‌گردد. صفحه‌ها این رفتار را با `useBackInterceptor(active, handler)` ثبت می‌کنند.
  2. بعد تاریخچهٔ ناوبری.
  3. بعد از ریشهٔ تب‌های دیگر به خانه.

### افزودن صفحهٔ تازه

1. فایل `screens/XScreen.tsx` را بسازید و از `Screen` و `ScreenChrome` برای قاب و سرتیتر استفاده کنید.
2. کلید را به `ScreenKey` در `navigation/types.ts` اضافه کنید.
3. در `CurrentScreen` (`Navigator.tsx`) کلید را به کامپوننت وصل کنید.
4. متن‌ها را در هر دو زبان در `i18n/strings.ts` بگذارید و با `t("key")` بخوانید.
5. فراخوانی API را در `api/endpoints.ts` و نوعش را در `api/types.ts` تعریف کنید.
6. اگر صفحه یک بخش تازه است، برایش تور بنویسید ([تور راهنما](#تور-راهنما-srctour)).

## ارتباط با API و کش

- **نشانی پایه:** `EXPO_PUBLIC_API_BASE_URL`. این مقدار هنگام **ساخت** داخل بسته قرار می‌گیرد. پیش‌فرضش `http://127.0.0.1:8000/api/v1` است و در بیلدهای production برابر `https://api.pharmenta.ir/api/v1`.
- **`client.ts`:**
  - **توکن:** توکن دسترسی را به هر درخواست اضافه می‌کند. با پاسخ 401، توکن را یک بار تمدید می‌کند؛ اگر چند درخواست هم‌زمان 401 بگیرند، همه منتظر همان یک تمدید می‌مانند.
  - **زمان انتظار:** ۴۵ ثانیه.
- **ذخیرهٔ ورود (`store/session.ts`):**
  - **محل ذخیره:** توکن‌ها در اندروید و iOS در `expo-secure-store` و در وب در AsyncStorage (localStorage) ذخیره می‌شوند.
  - **کلیدها:** `pharmexa.access`، `pharmexa.refresh`، `pharmexa.session`، و `pharmexa.user` برای آخرین پروفایل.
  - **حالت آفلاین:** اگر اپ بدون اینترنت باز شود، با آخرین پروفایل ذخیره‌شده وارد می‌شود و کاربر را بیرون نمی‌کند (`store/auth.ts`). فقط وقتی سرور واقعاً نشست را رد کند خارج می‌شود.
- **TanStack Query (`api/queryClient.ts`):**
  - **کش روی دستگاه:** پاسخ‌ها تا ۷ روز (`CACHE_MAX_AGE`) در AsyncStorage می‌مانند و با باز شدن دوبارهٔ اپ فوراً نمایش داده می‌شوند. اگر کهنه باشند، در پس‌زمینه تازه می‌شوند.
  - **کهنگی:** پیش‌فرض ۵ دقیقه. برای داده‌های مرجع (`calculators`، `calculator-categories`، `calculator`، `medscape-tree`) ۱ روز است، مگر اینکه پاسخ فهرست خالی باشد.
  - **درسنامهٔ دارو (`lesson-drug`)** از ۲۰۲۶-۱۱-۰۱ دیگر مرجع یک‌روزه نیست. ویرایش مرکز کیفیت داده در اپ اندروید تا یک روز دیده نمی‌شد، چون اپ کش را بین اجراها نگه می‌دارد. حالا درسنامه اول از کش نمایش داده می‌شود و هر بار که باز می‌شود، بی‌صدا دوباره گرفته می‌شود.
  - **حجم:** چون AsyncStorage مقدار بزرگ‌تر از حدود ۲ مگابایت را نمی‌خواند، کش پیش از ذخیره کوچک می‌شود.
  - **کوئری‌های آفلاین:** کوئری‌های جست‌وجوی UpToDate و Lexicomp و خواندن مقاله `networkMode: "always"` دارند تا بدون اینترنت متوقف نشوند و از بستهٔ آفلاین بخوانند.
  - **`CACHE_BUSTER`:** وقتی شکل یک پاسخ ناسازگار عوض می‌شود، این تاریخ را تغییر دهید تا کش قدیمی همهٔ کاربران دور ریخته شود.

## زبان، جهت و تم

- **زبان (`LanguageProvider`):**
  - **پیش‌فرض:** فارسی.
  - **ابزارها:** `t(key)` (متن)، `n(value)` (عدد با رقم فارسی)، `isFa`، `dir`، و `row` (`row-reverse` در فارسی) برای چیدمان افقی که در هر دو جهت درست بماند.
  - **متن ثابت:** هر متن رابط کاربری باید در `strings.ts` باشد، نه مستقیم در کامپوننت.
- **تم (`ThemeProvider`):**
  - **حالت:** روشن یا تیره، بر اساس سیستم یا انتخاب کاربر.
  - **رنگ‌ها:** فقط از `useTheme().colors` خوانده می‌شوند، نه کد رنگ مستقیم.
  - **مقادیر طراحی:** فاصله، گوشه و سایه از `theme/tokens.ts`.
- **فونت:** وزیرمتن (`@expo-google-fonts/vazirmatn`).
- **متن فارسی با کلمه‌های انگلیسی (`utils/bidi.ts`):** هر متنی که `AppText` در حالت فارسی نشان می‌دهد و حرف فارسی دارد، پیش از نمایش از این لایه می‌گذرد. هر خط با RLM شروع می‌شود، پس جهت پایهٔ آن راست‌به‌چپ است، حتی اگر جمله با کلمهٔ انگلیسی شروع شود. هر عبارت انگلیسی (`mg/kg/day`، `CYP3A4`، `COPD`) داخل LRI…PDI ایزوله می‌شود تا نقطه‌گذاری و پرانتزهای کنارش جابه‌جا نشوند. بین عدد و واحد هم فاصلهٔ نشکن می‌آید. متن کاملاً انگلیسی در حالت فارسی، مثل «None.»، یک تکهٔ ایزولهٔ چپ‌به‌راست است. متن دیتابیس دست نمی‌خورد و این کار فقط هنگام نمایش انجام می‌شود. برای متنی که باید چپ‌به‌راست بماند، `writingDirection: "ltr"` بدهید تا از این لایه رد نشود.

## نمایش بزرگ عکس و جدول

در مقاله‌های بیماری و گایدلاین، هر عکس یا جدول نشانهٔ «⤢» دارد. با لمس آن، `components/article/MediaViewer.tsx` صفحهٔ کاملی باز می‌کند. محتوای این صفحه یک HTML مستقل است (`mediaPage.ts`): روی وب در iframe و روی گوشی در WebView.
- **عکس:** با همان کیفیت ذخیره‌شده، روی زمینهٔ تیره نشان داده می‌شود. تا سه برابر پیکسل‌های خودش بزرگ می‌شود.
- **جدول:** با عرض طبیعی خودش نشان داده می‌شود، نه فشرده در ستون مقاله.
- **حرکت‌ها:** بزرگ‌نمایی با دو انگشت، دو ضربه (بزرگ‌نمایی روی نقطهٔ لمس) و چرخ موس، و جابه‌جایی با کشیدن. اسکریپت خود صفحه این کار را می‌کند، چون بزرگ‌نمایی مرورگر داخل iframe کل اپ را بزرگ می‌کرد.
- **بستن:** با «×» یا دکمهٔ برگشت (اندروید یا مرورگر).

## دانلود آفلاین (`src/offline/`)

مسیر دقیق فایل‌ها در هر پلتفرم، شرایط حفظ دانلودها پس از آپدیت اپ و روش جایگزینی بستهٔ دیتابیس در [13-offline-storage.md](13-offline-storage.md) مستند شده است.

هر بخش نسخهٔ بومی (`.ts`) و نسخهٔ وب (`.web.ts`) دارد:

| فایل | اندروید و iOS | وب |
|---|---|---|
| `crypto` | رمزگشایی AES-GCM با `expo-crypto`؛ کلید در SecureStore | Web Crypto؛ کلید غیرقابل‌استخراج در IndexedDB (`pharmenta-offline`) |
| `files` | `expo-file-system` در `Paths.document/offline/<dataset>/<build>`؛ بررسی MD5 | OPFS (فضای خصوصی مرورگر)؛ بررسی حجم |
| `downloader` | دانلود واقعی پس‌زمینه (`react-native-background-downloader`)، تنظیم «فقط Wi‑Fi» | Web Worker با ادامه از همان نقطه (Range)؛ فقط تا وقتی صفحه باز است |
| `serviceWorker` | بی‌کار | ثبت `public/sw.js` |

فایل‌های مشترک:
- **`store.ts`:** وضعیت هر بسته (نصب‌شده، در حال دانلود، مجوز). در `pharmenta.offline` ذخیره می‌شود.
- **`reader.ts`:** خواندن رکوردهای رمزشده.
- **`uptodateLocal.ts` و `lexicompLocal.ts`:** جست‌وجو و بررسی تداخل محلی، با همان نتیجه‌ای که سرور می‌دهد. UpToDate از مفهوم‌ها و ارتباط مقاله‌های snapshot استفاده می‌کند و تطبیق عنوان و تصحیح غلط املایی مسیر پشتیبان است. `uptodateSearchCatalog.ts` همتای کاتالوگ پایتون و `uptodateSearchSupplement.ts` ارتقای رمزگذاری‌شدهٔ جست‌وجوی بسته‌های قدیمی است؛ فایل‌ها و مجوز بسته حفظ می‌شوند.
- **`sources.ts`:** با بسته و مجوز معتبر ابتدا از دستگاه می‌خواند. نبود بسته، شکست خواندن یا نتیجهٔ `null` به API منتقل می‌شود؛ فهرست خالی یک پاسخ معتبر محلی است. `topicAtAnchor` استثناست: برای تطبیق hash و مقصد ابتدا سرور را می‌خواند؛ در خطای شبکه یا 503 به خواندن عادی مقاله برمی‌گردد، ولی خطاهای API دیگر را پنهان نمی‌کند. جایگزینی build نصب‌شدهٔ UpToDate، حافظهٔ آماده‌شدهٔ جست‌وجو و کوئری‌های `uptodate-search-page`، `uptodate-topic` و `uptodate-graphic-html` را بی‌اعتبار می‌کند. دریافت موفق مکملِ بستهٔ قدیمی نیز جست‌وجوی کش‌شده را تازه می‌کند.
- **`boot.ts`:** با عوض شدن کاربر و برگشتن اپ به پیش‌زمینه، مجوز را تمدید می‌کند. مجوز در هر شروع اپ و هر ۳۰ دقیقه بررسی می‌شود.

قواعد مجوز روی دستگاه:
- **اعتبار:** بسته تا ۳۰ روز بدون اینترنت قابل استفاده است.
- **وابستگی به کاربر:** بسته برای همان کاربری کار می‌کند که آن را دانلود کرده است.
- **عقب کشیدن ساعت:** اگر ساعت دستگاه بیش از ۱۰ دقیقه عقب کشیده شود، بسته قفل می‌شود.
- **پاسخ 402 یا 404 در تمدید:** بسته فوراً قفل و کلیدش پاک می‌شود.

## پروفایل: اشتراک

- **کارت «اشتراک شما» (`components/profile/SubscriptionCard.tsx`)** از `GET /billing/me/` ساخته می‌شود و پلنی را نشان می‌دهد که دیرتر از همه تمام می‌شود:
  - نام پلن و برچسب «فعال»
  - روزهای باقی‌مانده، با نواری که سهم مانده از کل دوره را نشان می‌دهد
  - تاریخ پایان (شمسی در فارسی)
  - برچسب «هدیهٔ یک‌ماههٔ ثبت‌نام» برای `source = "trial"`
  - از ۵ روز مانده، عدد و نوار قرمز می‌شوند و پیام «به پایان نزدیک است» می‌آید
  - بدون پلن: «رایگان» با یک خط توضیح
- **ردیف «خرید اشتراک»** صفحهٔ خرید داخل اپ (`screens/PlansScreen.tsx`، مسیر `plans`) را باز می‌کند. از ۲۰۲۶-۱۱-۰۲ خرید داخل خود اپ است؛ قبلاً صفحهٔ پلن‌های سایت در مرورگر باز می‌شد و کاربر باید آنجا دوباره وارد می‌شد.
  - **پلن‌ها** از `GET /billing/catalog/`: نام، شعار، نشان، قیمت هر مدت (با قیمت خط‌خورده و برچسب)، امکانات فهرست‌شده و خط‌های اضافه. بسته‌ها (`products`) زیر پلن‌ها می‌آیند.
  - **انتخاب:** لمس کارت یا یکی از مدت‌ها. بعد کد تخفیف (`POST /billing/quote/`)، جمع مبلغ، تخفیف و قابل پرداخت، و اگر بیش از یک درگاه روشن باشد، انتخاب درگاه.
  - **«پرداخت آنلاین»:** `POST /billing/checkout/` و باز کردن `payment_url`. روی اندروید با `Linking.openURL` در مرورگر، روی وب در همان زبانه. مسیر کامل در [05-api.md](05-api.md) آمده.
  - **بعد از پرداخت:** کارت وضعیت (در انتظار، فعال شد، ناموفق) از `GET /billing/orders/` ساخته می‌شود. وقتی اپ به جلو برمی‌گردد خوانده می‌شود، و تا وقتی `pending` است هر ۵ ثانیه. با `paid`، کارت اشتراک (`billing-me`) تازه می‌شود.
  - **نقطهٔ میانی:** کنار رقم فارسی «·» نیاید، چون مثل صفر خوانده می‌شود («۳۰ · مقاله» شبیه «۳۰۰» است). محدودیت امکانات داخل پرانتز می‌آید.
- مهمان‌ها کارت و ردیف را نمی‌بینند.

## UpToDate

- **جست‌وجو (`UptodateScreen.tsx`):**
  - **بارگذاری:** با `useInfiniteQuery` و `searchPage`، ۳۰ نتیجه در هر صفحه. صفحهٔ بعد نزدیک پایان فهرست خودش می‌آید؛ دکمهٔ «نمایش بیشتر» هم هست.
  - **بخش‌ها:** همهٔ تخصص‌های نتیجه‌ها در ردیف قابل اسکرول هستند و محدودیت چهار چیپ برداشته شده است. فیلتر با همهٔ تخصص‌های هر مقاله تطبیق می‌دهد، در سرور یا بستهٔ محلی. جست‌وجوی تازه به «همه» برمی‌گردد؛ در فارسی ابتدای ردیف از سمت راست دیده می‌شود.
  - **کشوی راهنمای جست‌وجو (`components/UptodateSuggestionMenu.tsx`):** طرح انتخاب‌شدهٔ مالک محصول. با تایپ ناقص و پس از debounce دویست میلی‌ثانیه باز می‌شود؛ عبارت‌ها با اولویت منبع، نوع و تعداد مقالهٔ مرتبط نمایش داده می‌شوند. فیلترهای همه/درمان/تشخیص/پیگیری ترتیب اصلی را حفظ می‌کنند. از همان پاسخ صفحهٔ جست‌وجو استفاده می‌شود و درخواست جداگانهٔ شمارش ندارد. دادهٔ قدیمیِ API بدون `kind/count` هم قابل نمایش است؛ نوع از عبارت تعیین می‌شود و شمارندهٔ ناموجود نمایش داده نمی‌شود. فهرست روی نتایج و در کنار خود کادر باز می‌شود؛ ارتفاع آن با فضای قابل مشاهده و کیبورد محدود می‌شود و اسکرول مستقل دارد. جهت عبارت پزشکی چپ‌به‌راست و متن راهنما تابع زبان اپ است. ArrowUp/Down، Enter، Escape، لمس بیرون کادر و بازگشت پشتیبانی می‌شوند؛ پاسخِ عبارت قبلی هنگام تایپ عبارت تازه پیشنهاد داده نمی‌شود. حالت بارگیری، بدون پیشنهاد، فیلتر خالی و خطای دریافت جدا هستند. نگاشت بستهٔ `search_schema: 1` برای محاسبهٔ محلی نوع و شمارنده کافی است و قالب باینری بسته تغییر نکرده است.
  - **عنوان‌ها:** پاک‌سازی تگ و entity در نتیجه، عنوان مقاله، گرافیک، پارامتر ناوبری و علاقه‌مندی‌های قدیمی اعمال می‌شود؛ کش و بستهٔ قبلی برای اصلاح عنوان پاک نمی‌شوند.

  - **دکمه‌ها:** ستاره، «Aa» (اندازهٔ متن)، فهرست مطالب و جست‌وجو.
  - **جست‌وجو در مقاله:** خانهٔ ۴۴ پیکسلی، با ▲ (مورد قبلی)، ▼ (مورد بعدی) و ✕ (بستن). Enter به مورد بعدی می‌رود.
  - **اندازهٔ متن:** ۹ پله از ۸۵٪ تا ۱۶۵٪ (`TEXT_SCALES` در `store/reader.ts`). همهٔ اندازه‌های صفحهٔ مقاله `rem` است، پس عوض کردن font-size ریشه (`__utdSetScale`) کل مقاله را بزرگ می‌کند. صفحه دوباره بار نمی‌شود و جای خواندن حفظ می‌شود. خوانندهٔ Medscape هم از همین مقدار استفاده می‌کند.
  - **Related:** گرافیک‌ها (به همان گروه‌بندی UpToDate: Algorithms، Tables، Figures، Pictures، ...)، ماشین‌حساب‌ها و مقاله‌های مرتبط، از بخش‌های `outlineRelated*` در `outline_html` (`parseRelated` در `utils/uptodateOutline.ts`). درست پیش از REFERENCES می‌آید و در فهرست مطالب هم ردیف دارد. لمس گرافیک آن را در نمایشگر باز می‌کند و لمس مقاله صفحهٔ آن مقاله را. روی ۲۰۰ مقالهٔ نمونه همهٔ ۳٬۲۰۰ لینک خوانده شد.
  - **جدول‌ها (`utils/uptodateTables.ts`):** طرح «مرجع دقیق» با حفظ سلول‌های ادغام‌شده، سرستون‌ها و ستون اول ثابت در نمای مقاله. لمس خود جدول داخل مقاله یا لینک جدول در Related، مستقیماً نمای تمام‌صفحه را باز می‌کند و پیش‌نمایش واسط ندارد. دکمهٔ «نمایش تمام‌صفحهٔ جدول» نیز برای دسترسی واضح و کیبورد حفظ شده است. انتخاب متن و لینک‌های داخل سلول، عملکرد خود را حفظ می‌کنند. نمای تمام‌صفحه ابتدا همهٔ ردیف‌ها و ستون‌ها را در فضای موجود جا می‌دهد؛ «کل جدول» همین نما را برمی‌گرداند و «تمام‌عرض» جدول را با عرض صفحه تنظیم می‌کند. زوم تا ۴۰۰٪ با دکمه، دو انگشت، دوبار لمس یا Ctrl+اسکرول و جابه‌جایی با کشیدن ممکن است. پاورقی‌ها بدون حذف در بخش بازشونده قرار دارند. بازگشت، Escape یا × نمایشگر را می‌بندد و مستقیم به همان مقاله با موقعیت قبلی برمی‌گردد؛ تصویرهای بدون جدول همچنان نمایشگر گرافیک خود را دارند. متن کنترل‌ها وارد جست‌وجو و offset هایلایت نمی‌شود. همان HTML/CSS/JS روی وب و WebView استفاده می‌شود و با دادهٔ آنلاین یا آفلاین کار می‌کند.
  - **هایلایت:** متن را انتخاب کنید تا نوار پنج رنگ زیر انتخاب بیاید. لمس هایلایت نوار را با دکمهٔ حذف باز می‌کند تا رنگ عوض یا حذف شود. هایلایتِ روی لینک با انتخاب دوباره حذف می‌شود، چون لمس لینک لینک را باز می‌کند.
    - **محل:** بازهٔ نویسه‌ها در متن بدنهٔ مقاله، بدون شمارهٔ سرفصل‌ها، Related و نوار.
    - **بررسی:** هر هایلایت یک hash از متن خودش دارد. اگر مقاله عوض شده باشد، هایلایت روی کلمهٔ دیگر نمی‌نشیند.
    - **ذخیره:** هایلایت‌ها و علاقه‌مندی‌ها فقط روی دستگاه می‌مانند (`store/library.ts`، `pharmenta.library`).

## قوانین و حریم خصوصی در ثبت‌نام

در صفحهٔ ثبت‌نام، «قوانین» و «حریم خصوصی» در جملهٔ «با ساخت حساب، قوانین و حریم خصوصی فارمنتا را می‌پذیری» قابل لمس‌اند. هرکدام متن کامل صفحهٔ همان‌نام سایت (`terms` و `privacy`، ویرایش در پنل سایت) را در یک صفحهٔ تمام‌صفحه نشان می‌دهد (`components/LegalSheet.tsx`، از `GET /app/legal/<slug>/`). پذیرفتن با همان جمله است و تیک جدا ندارد.

## نمایش گزینه‌های ماشین‌حساب

گزینه‌های ماشین‌حساب در `utils/calculatorLabels.ts` از هر دو فیلد `title_primary` و `title_secondary` (با معادل فارسی و fallback مستقل) ساخته می‌شوند؛ مقدار و واحد دوم عین دیتابیس است. حدود `<`، `>`، `≤`، `≥` و بازه‌ها هنگام نمایش به عبارت فارسی یا انگلیسی تبدیل می‌شوند، هم در پرسش و هم خلاصهٔ پاسخ‌ها؛ عامل امتیازدهی تغییر نمی‌کند.

- **کلید واحد SI و US (`UnitSystemSwitch`):** وقتی دو برچسب یک گزینه همان بازه در دو سیستم واحد باشند («34–50 µmol/L» و «2.0–3.0 mg/dL»)، بالای ماشین‌حساب یک کلید ظاهر می‌شود. هر طرف کلید با واحدهای خودش نام‌گذاری شده است (مثلاً «°C, µmol/L | °F, mg/dL»)، و گزینه‌ها فقط برچسب سیستم انتخاب‌شده را نشان می‌دهند.
  - پیش‌فرض، سیستمی است که بیشتر برچسب‌های اول همان ماشین‌حساب دارند.
  - تشخیص در `choiceUnitPair` از روی واحدِ بعد از عدد در فیلدهای انگلیسی انجام می‌شود.
  - جفتی که سیستمش روشن نیست (ng/mL و µg/mL)، برچسب بی‌واحد، و توضیح بالینی همیشه دوخطی می‌مانند: برچسب اول پررنگ، و دومی زیرش کوچک‌تر و کم‌رنگ‌تر.
  - کادرهای عددی کلید واحد خودشان را کنار کادر دارند و از این کلید پیروی نمی‌کنند.
- **فقط دکمهٔ «بعدی» جلو می‌برد.** انتخاب گزینه، حتی بله و خیر، به سؤال بعد نمی‌رود.
- **عدد تایپ‌شده** با `utils/typedNumber.ts` خوانده می‌شود: رقم فارسی و عربی، ممیز «٫»، «/» یا «,» به‌جای ممیز، و جداکنندهٔ هزارگان. همین برای کادر تاریخ و هفته و روز هم هست. پیش از این، عدد فارسی خالی حساب می‌شد و دکمهٔ «بعدی» بی‌دلیل خاموش می‌ماند.
- **دلیل خاموش بودن «بعدی»** همان لحظه زیر کادر نوشته می‌شود: عدد نامعتبر، یا خارج از بازهٔ مجاز با پیام خود ماشین‌حساب.
- **علامت درجه** («°C»، «°F») در `utils/bidi.ts` جزو عبارت انگلیسی کنارش است. پیش از این در متن فارسی «105.8 °F» به شکل «F° 105.8» دیده می‌شد.

بررسی رگرسیون نمایش، واحد، خواندن عدد و نصب: `cd frontend && node --test scripts/announcement-calculator.test.cjs`.

## وب‌اپ و PWA

برای ساخت اعلان نصب، در `/manage/` ← «اپ» ← «اعلانات اپ»، عنوان و متن را بنویسید و نوع دکمه را «نصب وب‌اپ (PWA)» انتخاب کنید. مخاطب به‌صورت خودکار «کاربران وب که وب‌اپ را نصب نکرده‌اند» می‌شود. پیش‌نمایش هر دو دکمه را نشان می‌دهد. می‌توان ابتدا «آزمایش روی گوشی من» را زد و بعد منتشر کرد. هنگام استقرار، migration جدید برنامهٔ `announcements` را با `python manage.py migrate` اعمال کنید.

- **آیکون وب‌اپ نصب‌شده (PWA):** از `frontend/assets/icons/Mortar.png` (انتخاب مالک پروژه، ۲۰۲۶-۱۱-۰۱).
  - `python3 frontend/scripts/brand_icons.py` همهٔ اندازه‌ها را می‌سازد: `favicon.png`، `icon-192.png`، `icon-512.png`، `icon-maskable-512.png` و `apple-touch-icon.png` در `frontend/public/`، به‌علاوهٔ آیکون‌های سایت.
  - آیکون iOS و آیکون maskable گوشه‌های سفید دارند. iOS شفافیت را سیاه می‌کند، و آیکون maskable باید کل مربع را پر کند (لوگو داخل ۸۰٪ امن است).
  - بعد از عوض کردن آیکون، `?v=` را در `manifest.webmanifest` و `index.html` یکی بالا ببرید تا وب‌اپ‌های نصب‌شده آیکون تازه را بگیرند. الان `?v=2` است.
- **خروجی:** `npx expo export --platform web` یک بستهٔ تک‌صفحه‌ای در `frontend/dist/` می‌سازد (`app.json`: `"output": "single"`).
- **سرو (`frontend/nginx.conf`):**
  - مسیر ناشناخته به `index.html` برمی‌گردد.
  - `index.html`، `manifest.webmanifest` و `sw.js` هرگز کش نمی‌شوند.
  - `/_expo/` و `/assets/` یک سال کش می‌شوند، چون نامشان با محتوا عوض می‌شود.
  - درخواست `http` به `https` هدایت می‌شود. بدون این، وب‌اپ روی `http` باز می‌شد و CORS بک‌اند آن را رد می‌کرد.
- **`public/sw.js`:**
  - **خود صفحه:** اول شبکه، و اگر نبود نسخهٔ ذخیره‌شده.
  - **فایل‌های `_expo/` و `assets/`:** اول کش.
  - **نتیجه:** وب‌اپ نصب‌شده بدون اینترنت هم باز می‌شود. درخواست‌های API و بسته‌های آفلاین از Service Worker نمی‌گذرند.
- **زیرمسیر:** برای سرو زیر یک مسیر (مثل GitHub Pages)، `EXPO_BASE_URL` را هنگام ساخت بدهید (`app.config.js`). روی `app.pharmenta.ir` خالی است.

## قواعد کدنویسی اپ

- **TypeScript:** برای هر پاسخ API نوع مشخص در `api/types.ts` تعریف شود. بعد از هر تغییر `npm run typecheck` بزنید.
- **ناوبری:** همهٔ صفحه‌ها `Screen` و `ScreenChrome` را برای قاب، سرتیتر و دکمهٔ برگشت به کار ببرند.

## چت آزمایشی منابع

ورودی خانه با پاسخ `ai-lab/status/` نمایش داده می‌شود. `AiLabScreen` برای Luna از `api/aiLab.ts` و بازیابی درخواست فعال استفاده می‌کند؛ گفتگو در `store/aiLab.ts` فقط در حافظهٔ همان حساب است. منبع فعلی ثابت و فقط UpToDate است. مقدمهٔ فارسی، ارجاع‌ها، بند بازشدنی منبع و مسیر مستقیم به همان بند مقاله نمایش داده می‌شوند. تعداد مقاله‌های بررسی‌شده و توقف با یافتن پاسخ کافی مشخص است؛ نتیجهٔ `partial` پیام پاسخ ناقص دارد. جست‌وجوی معمول و دانلودهای آفلاین تغییر نکرده‌اند. [شرح و محدودیت‌ها](25-reference-chat-lab.fa.md).

نتیجه‌های بررسی‌شده هنگام اجرای شغل، با polling یک‌ثانیه‌ای و `after_revision` دریافت می‌شوند. `findings` تجمعی است؛ یافته‌های قبلی در پاسخ بدون تغییر نسخه پاک نمی‌شوند. پس از خطا و پاسخ نهایی، شواهد قبلی برای مرور باقی می‌مانند؛ زمان اولین نتیجه هم نمایش داده می‌شود.

`ReferenceSearchProgress` لودینگ مرحله‌ای، عنوان‌های یافته‌شده، مقالهٔ فعلی، زیربخش‌ها و پیشرفت خواندن بندها را هنگام اجرا نمایش می‌دهد. مدل ثابت Luna است و انتخاب‌گر و مقایسهٔ مدل حذف شده‌اند.
