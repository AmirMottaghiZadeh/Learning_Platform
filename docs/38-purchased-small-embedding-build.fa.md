## نظارت و ادامه

اجرای مستقل از اتصال چت با `.private/run-full-small-embedding.py` شروع شد. فایل وضعیت و log خصوصی‌اند:

```bash
  --max-inputs 671000 --max-tokens 143000000 --batch-size 128 \
```

اگر درخواست نامطمئن علامت خورده باشد، retry فقط بعد از بررسی و با `--retry-uncertain` انجام شود؛ رزرو قبلی در سقف باقی می‌ماند. عوض‌کردن مدل/بُعد برای ادامهٔ همین نسل مجاز نیست. خطای دسترسی به معنی پاک‌شدن بردارهای موفق نیست.

۱۷ تست ذخیره‌سازی native، رزرو/ادامه، batch=128، منع fallback پولی در مسیر محلی و آداپتور بردار پاس شدند؛ compile و diff check نیز پاس شدند. پس از ساخت، شمار بردارها، سلامت HNSW، بازیابی/منابع و کیفیت/زمان باید بررسی شوند. head فعال، rollout عمومی و گیت کیفیت هنوز تغییر نکرده‌اند؛ هدف پاسخ نهایی زیر ۲۰ ثانیه همچنان نیازمند ارزیابی است.


### تکمیل بردارها و ساخت HNSW — بررسی ۲۰۲۶-۱۱-۱۳

هر **۶۷۰٬۹۹۱ بردار** در دیتابیس ذخیره شده و `pending_embedding_inputs=[]` است. رزرو تجمعی نهایی **۱۴۲٬۹۴۸٬۳۴۴ توکن**، همچنان کمتر از سقف ۱۴۳ میلیون، ثبت شده است؛ رزرو شامل درخواست‌های نامطمئن قبلی است و الزاماً برابر صورتحساب قطعی provider نیست. پس از تکمیل، مرحلهٔ `hnsw` شروع شده و هیچ درخواست embedding تازه‌ای در این مرحله لازم نیست.

PostgreSQL اجرای واقعی `CREATE INDEX CONCURRENTLY` با مرحلهٔ `building index: loading tuples` را گزارش کرد؛ یک پردازهٔ اصلی و دو worker فعال بودند. در نخستین نمونهٔ پایش، ۷۴۴۱ از ۱۸۶۸۵ صفحهٔ اسکن و ۲۴۳٬۲۵۸ tuple پردازش شده بود؛ این درصد اسکنِ مرحلهٔ جاری است، نه درصد زمان کل ساخت. حجم ایندکس در حال ساخت حدود ۱۹۰۰ MB بود. `indisready=false` و `indisvalid=false` در این مرحلهٔ در حال ساخت طبیعی‌اند؛ تا پایان ساخت، `embedding_ready=false` می‌ماند و نسل جدید head فعال نیست.

یک دستور پایش ابتدا به‌دلیل محدودیت shared memory سرویس Docker نتوانست segment اضافی ۱ MB بسازد؛ فایل‌های DSM موجود تقریباً سقف پیش‌فرض ۶۴ MB را مصرف کرده بودند، در حالی که بیش از ۲۱ GiB دیسک آزاد بود. همان پایش با `SET max_parallel_workers_per_gather=0` موفق شد و فعال بودن خود ساخت را تأیید کرد. این خطا را کمبود دیسک پروژه یا شکست خود HNSW فرض نکنید؛ در این بررسی هیچ build لغو یا container restart نشد. هنگام ساخت، پایش خواندنی را سریالی انجام دهید و فایل‌های shared memory را دستی حذف نکنید.
