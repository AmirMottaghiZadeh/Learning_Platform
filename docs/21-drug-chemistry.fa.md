# ۲۱. فرمول و ساختار شیمیایی داروها

وضعیت: پیاده‌سازی‌شده در کد و دیتابیس محلی؛ سیاست نهایی نمایش پیش‌فرض دادهٔ معتبر. تاریخ ثبت: ۲۰۲۶/۱۱/۰۹.

این قابلیت به دارونامه و کیفیت داده اضافه شده است. منبع داده PubChem PUG REST است؛ RDKit ساختار SMILES را می‌خواند، فرمول مولکولی آن را محاسبه و تصویر دوبعدی SVG را محلی تولید می‌کند. دادهٔ معتبر پیش‌فرض در اپ نمایش داده می‌شود و تأیید دستی پیش‌نیاز نمایش نیست. اپ برای نمایش تصویر به PubChem درخواست نمی‌فرستد؛ تصویر همراه پاسخ API از دیتابیس پروژه می‌آید.

## ذخیره‌سازی و هویت ماده

رابطهٔ اختیاری یک‌به‌یک `drugs.IngredientChemistry` به `Ingredient` اضافه شده است. جدول دارو و RxCUIهای موجود تغییر معنا نمی‌دهند. فیلدها شامل `molecular_formula`، `smiles` (با استریوشیمی دریافتی)، `inchikey`، `pubchem_cid`، `matched_name`، `structure_svg`، نامزدها، وضعیت، تاریخ دریافت و تأییدکننده است. نام انگلیسی و RxCUI زمان دریافت نیز ذخیره می‌شوند؛ تغییر هویت دارو، نمایش دادهٔ قبلی را متوقف می‌کند و آن را برای دریافت و بازبینی دوباره به صف می‌آورد. URL منبع از CID ساخته می‌شود. تاریخچهٔ دریافت و تصمیم‌ها در `ChemistryReview`، شامل snapshot اطلاعات ترکیب، ثبت می‌شود.

RxCUI شناسهٔ PubChem نیست. دریافت خودکار با نام کامل ماده انجام می‌شود؛ نتیجهٔ یکتا فقط یک **نامزد نیازمند بازبینی** است. چند نتیجه با وضعیت `ambiguous` و عدم نتیجه با `not_found` ذخیره می‌شود. انتخاب اولین نتیجه از چند ترکیب انجام نمی‌شود. نمک‌ها، استرها، مخلوط‌ها و فرآورده‌های زیستی نیاز به توجه ویژه دارند؛ پوشش کامل همهٔ مواد تضمین نشده است.

RDKit باید فرمول ساختار دریافتی را از نظر تعداد هر عنصر و بار الکتریکی با فرمول PubChem برابر تشخیص دهد (ترتیب نوشتن عناصر می‌تواند متفاوت باشد)؛ موارد نامعتبر، بیش از ۵۰۰ اتم، SMILES طولانی‌تر از ۲۰ هزار نویسه یا اختلاف ترکیب اتمی/بار الکتریکی به‌عنوان خطا باقی می‌مانند و خودکار منتشر نمی‌شوند. این محدودیت برای نمایش مولکول‌های کوچک است؛ نمودار پروتئین/پلیمر یا نمایش سه‌بعدی تولید نمی‌شود.

## نصب و دریافت اطلاعات

### محیط توسعهٔ محلی

از پوشهٔ `backend`:

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py import_pubchem --workers 4
```

### سرور: ابتدا احراز انتشار کد، سپس دریافت داده

کامیت و push فقط کد مخزن را به‌روز می‌کنند. برای اجرای فرمان تازه، سرویس **بک‌اند** باید از شاخهٔ `main`، با کامیت `9da9c2d` یا نسخهٔ پس از آن که این فایل‌ها را دارد، دوباره build و deploy شود. انتشار وب‌اپ روی `deploy-web` مستقل است. restart همان تصویر قبلی، کد تازه را وارد کانتینر نمی‌کند.

پس از موفق شدن build و rollout بک‌اند، ترمینال قبلی را ببندید و ترمینال کانتینر جدید را باز کنید. در تصویر استاندارد این پروژه، مسیر فعلی `/app` است و پوشهٔ `backend/` مستقیماً داخل آن کپی شده است:

```bash
python manage.py help import_pubchem
python manage.py showmigrations drugs
python -c "from rdkit.Chem.Draw import rdMolDraw2D; print('RDKit drawing: OK')"
```

فرمان باید شناخته شود، migrationهای `0010_chemistryreview_ingredientchemistry` و `0011_ingredientchemistry_ingredient_name_and_more` در فهرست باشند و import رسم RDKit موفق شود. سپس:

```bash
python manage.py migrate --noinput
python manage.py import_pubchem --workers 4
```

entrypoint همین پروژه هنگام شروع کانتینر migrate را اجرا می‌کند؛ بنابراین اگر فایل‌های جدید حاضر باشند و migrationها قبلاً اجرا شده باشند، پاسخ «No migrations to apply» طبیعی است. این پیام بدون بررسی نسخهٔ کد، به‌روز بودن schema نسبت به کامیت جدید را ثابت نمی‌کند.

**خطای گزارش‌شدهٔ `Unknown command: 'import_pubchem'`:** در رخداد بررسی‌شده، remote شاخهٔ `main` روی `9da9c2d` بود و وجود فایل فرمان و migrationها در همان کامیت تأیید شد. محیطی که فرمان را نمی‌شناخت، فرمان جدید را بارگذاری نمی‌کرد. لاگ بعدی علت این رخداد را مشخص کرد: Build کامیت جدید هنگام import RDKit به‌دلیل نبود libexpat.so.1 شکست خورده بود و نسخهٔ قبلی در حال اجرا مانده بود. بستهٔ libexpat1 به هر دو Dockerfile بک‌اند اضافه شده است؛ شرح کامل و بررسی اصلاح در [سند انتشار](08-deployment.md#علت-تأییدشدهٔ-شکست-build-کامیت-9da9c2d) آمده است. شاخه و کامیت انتشار بک‌اند، نتیجهٔ build/rollout و جدید بودن ترمینال کانتینر باید بررسی شوند. برای بررسی فایل‌های همان کانتینر:

```bash
ls apps/drugs/management/commands/import_pubchem.py
ls apps/drugs/migrations/0010_chemistryreview_ingredientchemistry.py
ls apps/drugs/migrations/0011_ingredientchemistry_ingredient_name_and_more.py
```

اگر فایل فرمان وجود دارد ولی هنوز شناخته نمی‌شود، مسیر اپ بارگذاری‌شده و کشف فرمان را بررسی کنید:

```bash
python manage.py shell -c "from django.apps import apps; from django.core.management import get_commands; print(apps.get_app_config('drugs').path); print(get_commands().get('import_pubchem'))"
```

فایل یا وابستگی را دستی داخل کانتینر قبلی کپی/نصب نکنید تا جای build جدید را بگیرد؛ تغییرات کانتینر با انتشار بعدی از دست می‌روند. RDKit و کتابخانه‌های رسم باید در تصویر ساخته‌شده نصب باشند. نتیجهٔ تشخیص بالا بدون نیاز به چاپ env یا اطلاعات اتصال دیتابیس قابل بررسی است.

کتابخانهٔ RDKit از طریق requirements نصب می‌شود. برای نمونهٔ محدود:

```bash
python manage.py import_pubchem --rxcui 161 --rxcui 5640
python manage.py import_pubchem --limit 20
```

`--workers` بین ۱ تا ۴ است (پیش‌فرض ۱)؛ همهٔ workerهای همان فرایند مجموعاً حداکثر حدود چهار درخواست در ثانیه می‌فرستند. چند importer هم‌زمان اجرا نکنید. درخواست‌ها timeout و retry محدود دارند. قطع ارتباط به‌عنوان «یافت نشد» ثبت نمی‌شود. اجرای مجدد فقط مواد فاقد رکورد و نامزدهای pending قدیمی با نام زمان دریافتِ خالی را تلاش می‌کند؛ سایر رکوردهای دریافت‌شده و تصمیم‌های قبلی را بازنویسی نمی‌کند. خطاهای هر RxCUI در stderr و شمارش انتهایی گزارش می‌شوند؛ در صورت وجود خطا exit code غیرصفر است، حتی اگر دریافت بخشی از مواد موفق شده باشد.

برای دریافت دوبارهٔ یک رکورد موجود، از صفحهٔ همان دارو در کیفیت داده استفاده کنید. دریافت موفق تازه، تأیید پیشین را لغو و اطلاعات را دوباره نیازمند بازبینی می‌کند؛ شکست شبکه دادهٔ قبلی را حفظ می‌کند. قفل تراکنش و نسخهٔ فرم مانع بازنویسی تصمیم هم‌زمان می‌شوند. هیچ ورود داده‌ای خودکار تأیید نمی‌شود.

## مدیریت و انتشار

در `/manage/data/`، فیلتر «بازبینی اطلاعات شیمیایی» نامزدهای نیازمند بررسی، تأییدهای دارای هویت تغییریافته، تطبیق‌های چندگانه و مواد یافت‌نشده را نشان می‌دهد و «باز کردن» صفحهٔ اطلاعات شیمیایی را باز می‌کند. از فضای بازبینی هر دارو نیز لینک «فرمول و ساختار شیمیایی» در دسترس است:

`/manage/data/drugs/<slug>/chemistry/`

ویرایشگر یا تأییدکننده می‌تواند نامزد را دریافت کند یا CID صحیح را دستی تعیین کند. تعیین CID معتبر، نمایش پیش‌فرض را فعال می‌کند ولی به معنی تأیید بازبینی نیست. تأییدکننده می‌تواند نام ماده، شکل پایه/نمک/استر، منبع و ساختار را بررسی و «تأیید بازبینی اطلاعات شیمیایی» را انتخاب کند. مجوز همان `accounts.approve_data_quality_suggestion` است. تأیید کلی دارو، خلاصه‌ها و تأیید شیمیایی مستقل‌اند. رد تطبیق، نمایش در اپ را حذف می‌کند. همهٔ تغییرات POST با CSRF و کنترل نسخه انجام می‌شوند.

## API و اپ

پاسخ جزئیات دارو (`GET /api/v1/drugs/<slug>/`) و درسنامه (`GET /api/v1/lessons/drugs/<slug>/`) فیلد اختیاری `chemistry` دارد:

```json
{
  "chemistry": {
    "molecular_formula": "C8H9NO2",
    "structure_svg": "<svg ...>...</svg>",
    "pubchem_cid": 1983,
    "source_url": "https://pubchem.ncbi.nlm.nih.gov/compound/1983",
    "fetched_at": "2026-11-09T12:00:00Z"
  }
}
```

برای دادهٔ غایب، ناقص، ردشده، چندتطبیقی، یافت‌نشده یا با هویت تغییریافته مقدار `null` است؛ اپ کل کادر را پنهان می‌کند. دادهٔ معتبر با وضعیت `pending` یا `approved` نمایش داده می‌شود؛ فهرست نامزدهای چندگانه و هویت تأییدکننده در API عمومی نیستند. پاسخ لیست داروها تصویر را حمل نمی‌کند. نسخه‌های قدیمی اپ فیلد جدید را نادیده می‌گیرند. اپ با `react-native-svg` موجود، تصویر را روی وب و اندروید نمایش می‌دهد؛ ارقام تعداد اتم‌ها به‌شکل زیرنویس و متن فرمول چپ‌به‌راست نمایش داده می‌شوند. تصویر روی زمینهٔ سفید خوانا می‌ماند، حتی در حالت تیره. لینک منبع از CID ساخته می‌شود و تنها برای بازکردن صفحهٔ منبع به شبکه نیاز دارد.

مانند سایر داده‌های دارونامه، آخرین پاسخ دریافت‌شده ممکن است در کش اپ باقی بماند؛ هنگام بازکردن آنلاین، جزئیات دوباره دریافت می‌شود. این قابلیت بخشی از بسته‌های آفلاین Lexicomp/UpToDate نیست. فرمان‌های فعلی export/import مرجع OpenFDA اطلاعات شیمیایی را منتقل نمی‌کنند؛ برای انتقال بین محیط‌ها از بکاپ PostgreSQL یا اجرای دریافت در محیط مقصد استفاده کنید؛ دادهٔ معتبر در مقصد نیز پیش‌فرض دیده می‌شود و بازبینی دستی اختیاری است.

## نتیجهٔ اجرای محلی در ۲۰۲۶/۱۱/۰۹

در اجرای اولیه (پیش از تغییر سیاست نمایش پیش‌فرض)، پس از اعمال migrationهای 0010 و 0011 و اجرای دریافت روی دیتابیس محلی، هر ۱٬۷۹۴ ماده رکورد اطلاعات شیمیایی دارد: ۱٬۴۲۶ نامزد با فرمول و SVG معتبر در انتظار بازبینی، ۱۴ تطبیق چندگانه و ۳۵۴ مورد یافت‌نشده. دو اختلاف ناشی از ترتیب عناصر (مانند HF در برابر FH) با مقایسهٔ تعداد اتم‌ها و بار رفع و مجدداً دریافت شدند. هیچ نامزدی روی دیتابیس اصلی محلی خودکار تأیید نشده است. این آمار وضعیت محلی همان تاریخ است و به معنی انتقال داده یا انتشار روی سرور نیست.

اعتبارسنجی: ۸۸۴ تست مجموعهٔ کامل بک‌اند و پس از اصلاحات نهایی ۱۴۳ تست مرتبط موفق شدند؛ typecheck و build:web موفق بودند. نمایش فارسی/انگلیسی، روشن/تیره، عرض‌های ۱۴۴۰، ۷۶۸ و ۳۹۰ پیکسل، و چرخهٔ اولیهٔ دریافت PubChem → عدم انتشار نامزد → تأیید → نمایش API → رد → پنهان‌شدن در دیتابیس پیش‌نمایش مستقل بررسی شدند. lint دو جزء جدید رابط بدون خطا و هشدار بود. ساخت تصویر Docker به‌علت نبود دسترسی به socket daemon در این محیط اجرا نشد؛ وابستگی‌ها و smoke check مربوطه به Dockerfile افزوده شده‌اند.

## سیاست نمایش پیش‌فرض

با درخواست مالک پروژه، ۱٬۴۲۶ رکورد معتبر محلی بدون نیاز به تأیید دستی در اپ قابل مشاهده‌اند. وضعیت‌های بازبینی موجود تغییر نمی‌کنند؛ نامزد بازبینی‌نشده `pending` می‌ماند و هیچ تأیید یا نام بازبینی‌کننده‌ای جعل نمی‌شود. رد تطبیق، فقدان هر یک از CID/فرمول/SMILES/SVG/تاریخ دریافت و تغییر هویت دارو همچنان مانع نمایش‌اند. دریافت موفق دوباره، دادهٔ معتبر را نمایش می‌دهد و وضعیت بازبینی را به pending برمی‌گرداند. این تغییر نیاز به migration یا تغییر داده‌های موجود ندارد.


## قرارداد نهایی نمایش

| وضعیت اطلاعات | نمایش در اپ | اقدام در مدیریت |
|---|---|---|
| `pending` با تمام اطلاعات معتبر و هویت فعلی | بله؛ تأیید دستی لازم نیست | تأیید بازبینی، رد یا دریافت مجدد |
| `approved` با تمام اطلاعات معتبر و هویت فعلی | بله | رد یا دریافت مجدد |
| `rejected` | خیر | دریافت دوباره برای بررسی تطبیق تازه |
| `ambiguous` | خیر | انتخاب CID صحیح و دریافت اطلاعات |
| `not_found` | خیر | بررسی منبع و دریافت دستی با CID، در صورت وجود |
| اطلاعات ناقص یا نام/RxCUI تغییرکرده | خیر | دریافت و تطبیق دوباره |

نمایش عمومی به معنی سبز شدن برچسب «بازبینی دارو» نیست. این برچسب همچنان جریان مستقل خود را دارد. نام فارسی `name_fa` نیز به پاسخ دارو اضافه شده تا عنوان دارو در حالت فارسی به انگلیسی برنگردد؛ در صورت نبود نام فارسی، همان fallback قبلی استفاده می‌شود.

## بررسی پس از تغییر سیاست نمایش

۱۴۴ تست مرتبط پس از فعال شدن نمایش پیش‌فرض گذشتند. آزمون‌ها نمایش pending بدون تأیید، پنهان ماندن rejected/ambiguous/not_found/ناقص، جلوگیری از انتشار ساختار مربوط به هویت قبلی، استقلال بازبینی کل دارو، CSRF، دسترسی نقش‌ها، نسخهٔ فرم، خطای شبکه و ادامهٔ دریافت را پوشش می‌دهند. شمارش مستقیم با منطق serializer روی دیتابیس محلی نیز نمایش ۱٬۴۲۶ مورد را تأیید کرد؛ تصمیم‌های بازبینی قبلی تغییر نکردند.

برای تکرار تست‌های مرتبط از `backend`:

```bash
.venv/bin/python manage.py test apps.drugs.test_chemistry apps.drugs.tests apps.lessons apps.data_quality_center --noinput
.venv/bin/python manage.py check
.venv/bin/python manage.py makemigrations --check --dry-run
```

اجرای ثبت‌شدهٔ مجموعه‌های ۸۸۴ و ۱۴۴ تایی از تنظیمات موقت تست با hasher سریع MD5 استفاده کرد؛ این تنظیم فقط برای تست بود و وارد تنظیمات برنامه یا محیط production نشده است. گزارش تصویری و داده‌های ورود پیش‌نمایش موقت‌اند و در مخزن ذخیره نمی‌شوند. دیتابیس اصلی، اطلاعات ورود، بسته‌های ساخته‌شده و خروجی dist نیز بخشی از کد قابل کامیت نیستند.

قابلیت SAR در این تغییر پیاده‌سازی نشده؛ نتیجهٔ بررسی منبع و مرز کار بعدی در [سند ۲۲](22-pubchem-sar-research.fa.md) ثبت شده است.


## اصلاح وابستگی Docker پس از دریافت لاگ رانفلر

کتابخانهٔ رسم RDKit در تصویر slim به `libexpat.so.1` وابسته است؛ این فایل را بستهٔ Debian با نام `libexpat1` فراهم می‌کند. نصب موفق pip به‌تنهایی حضور این کتابخانهٔ سیستمی را تضمین نمی‌کند. اکنون Dockerfile ریشه و backend/Dockerfile هر دو بستهٔ لازم را نصب و بارگذاری rdMolDraw2D را در build بررسی می‌کنند. CI نیز job تازهٔ backend-image برای ساخت تصویر ریشه دارد. تست محلی رسم SVG موفق بود؛ ساخت کامل Docker در محیط محلی به‌دلیل دسترسی نداشتن به daemon تأیید نشده است. این اصلاح migration تازه یا تغییر در داده‌های دارویی لازم ندارد؛ دریافت سرور پس از انتشار موفق تصویر اصلاح‌شده انجام می‌شود.
