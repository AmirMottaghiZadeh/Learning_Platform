# مستندات فارمنتا

فارمنتا (Pharmenta) اپ آموزشی داروسازی است: دارونامهٔ دوزبانه، آزمون، برنامهٔ مطالعه، مرجع‌های بالینی (UpToDate، Lexicomp، Medscape)، ماشین‌حساب‌های بالینی و فروش اشتراک. این پوشه مرجع واحد همهٔ اطلاعات فنی پروژه است، از نوشتن کد تا دیپلوی و نگهداری.

نقشهٔ ساختار و جریان فایل‌ها در ۲۰۲۶-۱۱-۰۷ با کد محلی تطبیق داده شد. برای دنبال کردن شروع اپ، درخواست API، جست‌وجو، بستهٔ آفلاین و انتشار، از [16-code-flows.md](16-code-flows.md) شروع کنید. سندهای ۱۴ و برنامهٔ جست‌وجو معماری هدف و کارهای باقی‌مانده را هم دارند؛ وضعیت پیاده‌سازی فعلی در نقشه و سندهای ۳ تا ۵ مشخص شده است.

> نام قدیمی پروژه «Pharmexa» بود. این نام هنوز در شناسه‌های فنی دیده می‌شود (مثلاً `slug` پروژهٔ EAS، دیتابیس `pharmexa_dev`، کلیدهای ذخیره‌سازی `pharmexa.*`). این شناسه‌ها عمداً عوض نشده‌اند، چون تغییرشان داده‌ها و نصب‌های موجود را می‌شکند. شناسهٔ بستهٔ اپ پیش از اولین انتشار به `com.pharmenta.learning` عوض شد.

## قرارداد نگهداری این مستندات

- هر تغییری که رفتار، دستور، متغیر محیطی یا مسیر API را عوض می‌کند، در همان کامیت در فایل مربوط ثبت شود.
- تغییر زنجیرهٔ فایل‌ها و منبع داده در [نقشهٔ جریان](16-code-flows.md) هم ثبت شود. طرح‌های آینده را با مسیر عملیاتی فعلی مشخصاً جدا کنید؛ ساخت زیرساخت یا نمونهٔ آزمایشی را به معنی انتشار قابلیت ننویسید.
- گزارش‌های [search/history/](search/history/README.md) سابقه‌اند. ارجاع به فایل حذف‌شده به شکل مسیر آرشیوی نوشته می‌شود؛ پیوند به فایل موجود باید از محل فعلی سند قابل باز شدن باشد.
- مقدار هیچ رازی (کلید، رمز، توکن) در این مستندات نوشته نمی‌شود؛ فقط نام متغیر و جای نگهداری‌اش. فهرست رازها در [09-operations.md](09-operations.md#رازها-و-چیزهایی-که-باید-امن-نگه-داشته-شوند) است.
- مسیرهای لپ‌تاپ توسعه (مثل `/home/amir/Documents/...`) همان پیش‌فرض‌هایی هستند که در کد آمده‌اند. روی سیستم دیگر با گزینهٔ `--source` یا متغیر محیطی عوض می‌شوند.
- شکل دقیق هر پاسخ API در Swagger زنده هم هست: `https://api.pharmenta.ir/api/v1/docs/`.
