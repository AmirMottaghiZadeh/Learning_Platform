# سه طرح تنظیم دوز اطفال

وضعیت: **طرح ۲ توسط کاربر انتخاب و در اپ پیاده‌سازی شد.** این پوشه آرشیو سه پیش‌نمایش اولیه است؛ نسخهٔ واقعی در `PediatricDoseScreen.tsx` است. [مستند قابلیت](../../20-pediatric-dose.fa.md).

نام: **تنظیم دوز اطفال / Pediatric Dose Adjustment**.

جایگاه نهایی: **ماشین‌حساب‌های بالینی ← کودکان / Pediatrics ← تنظیم دوز اطفال**. در کد فعلی، Pediatrics یک دامنهٔ موجود است (شناسهٔ محلی ۲۰۳). شناسهٔ عددی در انتشار نباید ثابت فرض شود؛ دسته با ساختار واقعی کاتالوگ پیدا می‌شود. کاتالوگ محلی اکنون ۴۸۳ ماشین‌حساب دارد و ابزار تازه ورودی مستقلی در همین دامنه خواهد بود؛ دسته‌های فعلی ادغام یا جایگزین نمی‌شوند.

## مشاهده و انتخاب

از ریشهٔ مخزن:

```bash
python3 -m http.server 8767 --bind 127.0.0.1
```

سپس [صفحهٔ مقایسه](comparison.html) را در `http://127.0.0.1:8767/docs/designs/pediatric-dose/comparison.html` باز کنید. فونت وزیرمتن از وابستگی نصب‌شدهٔ فرانت‌اند خوانده می‌شود؛ پیش‌نیاز `cd frontend && npm ci` است.

- **طرح ۱، فرم یک‌صفحه‌ای:** مشخصات کودک، دارو، اندیکاسیون، فرآورده و نتیجه در یک جریان پیوسته. مناسب وقتی کاربر می‌خواهد همهٔ ورودی‌ها را کنار هم ببیند.
- **طرح ۲، مرحله‌ای:** مشخصات کودک ← دارو و رژیم ← نتیجه. مناسب استفادهٔ هدایت‌شده و ورود اطلاعات به ترتیب. تصویر مقایسه گام نتیجه را نشان می‌دهد؛ لینک مستقل از گام اول شروع می‌شود.
- **طرح ۳، بالینی فشرده:** نوار خلاصهٔ کودک با ویرایش بازشونده، انتخاب دارو و تب‌های پاسخ، فرآورده‌ها و منبع. مناسب مراجعه و تغییر مکرر دارو برای همان ورودی‌های بیمار.

لینک‌های مستقیم در سرور محلی:

- [طرح ۱](index.html?design=1)
- [طرح ۲](index.html?design=2)
- [طرح ۳](index.html?design=3)

مقدارهای اولیه صرفاً نمونهٔ بررسی رابط‌اند. ورودی‌ها در مرورگر ذخیره نمی‌شوند. «بیمار جدید» ورودی و نتیجه را پاک می‌کند. نسخهٔ نهایی باید با ورودی خالی شروع شود.

## داده و منطق

منبع کاربر: `/home/amir/Documents/Medscape/peds_dose/`. نسخهٔ پیش‌نمایش شامل ۵۰ مدخل و ۲۳۳ رژیم است. `vendor/engine.js` بایت‌به‌بایت همان `src/engine.js` است؛ تمام تعریف‌های دارو در `vendor/drugs.json` بدون تغییر قواعد، سقف‌ها، نقل‌قول‌ها یا قدرت فرآورده کپی شده‌اند. هش SHA-256 همهٔ ورودی‌ها در [vendor/provenance.json](vendor/provenance.json) است.

همهٔ مقادیر رابط از همین موتور به دست می‌آیند؛ عددِ محاسباتی جداگانه یا دوز نمایشیِ ثابت در HTML نوشته نشده است. رژیم و فرآورده قابل انتخاب‌اند. GA وابسته به قواعد موتور آشکار و اجباری می‌شود؛ ورودی خالی به ۴۰ هفته تبدیل نمی‌شود. `ok: false` به پیام عدم امکان ارائهٔ فرآورده تبدیل می‌شود و حجم پیشنهاد نمی‌شود. پیام‌ها، سقف‌ها، دفعات، برنامهٔ روزهای مصرف و متن پشتوانه نگه داشته شده‌اند. برچسب‌های فارسی نام دارو فقط لایهٔ نمایش‌اند و تعریف‌های منبع را تغییر نمی‌دهند.

این داده بر اساس سن، وزن و اندیکاسیون است. تنظیم دوز کلیوی/کبدی در موتور منبع پیاده نشده است. تاریخ کپی داده به معنی تاریخ بازبینی مونوگراف پزشکی نیست. محدودیت‌های علمی و فرآورده‌ها در README و FIXES منبع کاربر باقی‌اند.

## تصمیم طراحی و بررسی

از مهارت `design-taste-frontend` استفاده شد: جهت `framed-sheet`، seed `641853394`، با حفظ palette/type برند. رنگ‌ها از `frontend/src/theme/tokens.ts`، وزیرمتن و ناوبری سه‌گزینه‌ای فعلی گرفته شده‌اند. به دلیل درخواست تطبیق با اپ موجود، پوستهٔ موبایل ۴۳۰ پیکسل و گوشه‌های فعلی حفظ شده‌اند؛ قاب با sidebar کتابخانه برای این صفحهٔ موبایل استفاده نشده است. نقطهٔ کانونی هر سه طرح مقدار هر نوبتِ فرآوردهٔ انتخابی است. glyphهای انتخاب و تغییر تم همان کنترل‌های رایج اپ هستند و برای همین موارد معافیت lint ثبت شده است.

۴۲ تست موتور/داده و رگرسیون منبع موفق بودند. بررسی منابع در پایگاه دادهٔ واقعی محلی: ۲۴۷ نقل‌قول، صفر ناموجود و صفر خطا. نسخهٔ کپی موتور و همهٔ ۵۰ تعریف دارو با منبع و هش‌ها تطبیق داده شدند. گزارش تعامل، فارسی/انگلیسی، تم روشن/تیره، GA، پاک‌کردن بیمار و عرض‌های ۳۷۵/۷۶۸/۱۴۴۰ در [browser-check.json](browser-check.json) و تصاویر در [screenshots/](screenshots/) قرار دارند.

## پیاده‌سازی منتخب

طرح ۲ با اجزای React Native به صفحهٔ واقعی تبدیل شد؛ iframe پیش‌نمایش در اپ استفاده نشده است. ورودی مستقل زیر Pediatrics و جست‌وجوی ماشین‌حساب‌ها از `includePediatricDose` می‌آید. API محافظت‌شده `/calculators/pediatric-dose/` داده‌ها را تحویل می‌دهد و موتور سمت دستگاه کار می‌کند. مشخصات اولیه خالی است؛ بازگشت از منبع UpToDate ورودی مرورشده را فقط از حافظهٔ ناوبری برمی‌گرداند. شرح مسیر فایل‌ها، نسخه‌بندی موتور و تست‌ها در [سند ۲۰](../../20-pediatric-dose.fa.md) آمده است.

نتیجهٔ نهایی این دور طراحی: ۶ گروه بررسی تعاملی و ۹ بررسی viewport، بدون خطا یا یافتهٔ باقیمانده؛ lint طراحی نیز بدون FAIL/WARN. TypeScript و بیلد وب اپ اصلی موفق بودند.
