# سرچ، رسانهٔ اصلی، PDF، ایمیل و مسیر بالینی — ۲۰۲۶-۱۱-۱۳

به‌روزرسانی ۲۰۲۶-۱۱-۱۴: ترتیب فعلی **رسانه ← پاسخ فارسی ← منابع مرتبط** است؛ رزرو اعتبار حذف و طرح انتخاب روش ورود نیز نهایی شد. سیاست جاری در [سند ۴۳](43-smart-search-postpay-quality-ai.fa.md) است. مطالب ترتیب و اعتبار این نسخهٔ اولیه با سند ۴۳ جایگزین می‌شوند.

## تصمیم‌های نهایی مالک

- ظاهر سرچ: **طرح ۲، گفت‌وگوی پیوسته**؛ [سه پیش‌نمایش](designs/smart-search/index.html) با دادهٔ نمونه نگه‌داری می‌شوند.
- سؤال ← منابع اصلی و رسانهٔ منتخب ← باکس بستهٔ «دیدن بخش‌های مرتبط در منابع» ← پاسخ فارسی و بازخورد. skeleton و پیش‌نویس پاسخ در همان محل انتهایی هستند.
- شارژ: بسته‌های ۱۰۰، ۵۰۰ و ۱۰۰۰، هدیهٔ اولیهٔ ۱۰۰، قیمت فروش تابع نرخ تومان و ضریب دلاری؛ جزئیات مالی در [سند ۴۱](41-smart-search-credits.fa.md).
- دو در ورودی خانه: آموزش و بالینی. ماشین‌حساب، گایدلاین و بیماری‌ها و شرایط داخل بالینی هستند.
- ورود با کد ایمیل فعال است. مالک دریافت ایمیل آزمایشی واقعی را تأیید کرد؛ ارسال جدید خودکار برای آزمایش انجام نشود.

## جست‌وجوی جدول و تصویر

دادهٔ اصلی همچنان فایل‌های محلی UpToDate است. مدل تصویر جدید یا جدول تازه نمی‌سازد. `ReferenceMedia` در دیتابیس مستقل `reference_search`، عنوان مقاله، عنوان/توضیح تصویر، متن جدول و کلید بازکردن اصل منبع را نگه می‌دارد. GIN متن انگلیسی مکمل بردارهای فعلی است؛ embedding جدید ساخته نمی‌شود.

`build_reference_media` رسانه‌های داخل مقاله و گرافیک‌های پیوندخورده را ثبت می‌کند؛ شناسه از مقاله، نوع و جایگاه رسانه ساخته می‌شود. `IndexedArticle.media_built` نقطهٔ ادامه است. هر مقاله همراه رکوردهایش اتمی نوشته می‌شود. رسانهٔ مشترک در چند مقاله با ارجاع همان مقاله ثبت می‌شود؛ تعداد موارد برابر تعداد تصاویر یکتای کل دیتابیس نیست.

درخواست دارای «جدول/تصویر/شکل/نمودار/الگوریتم» در کنار بازیابی فعلی، عنوان و توضیح رسانه را جست‌وجو می‌کند. نوع جدول/تصویر و جمعیت بیمار رعایت می‌شود. کلمات عمومی درمان/کودکان به‌تنهایی نام بیماری محسوب نمی‌شوند؛ نتیجه‌ای که فقط در متن جدول اشاره‌ای گذرا به بیماری دارد، با مقالهٔ موضوع اصلی برابر نیست. تا سه رسانه به شواهد اضافه می‌شود؛ مجوز و سهمیهٔ منبع کنترل می‌شود.

مدل فقط متن/شرح دریافت‌شده را توضیح می‌دهد و مجاز به ادعای تفسیر پیکسل تصویر نیست. جدول بیش از ۱۲ هزار نویسه به‌صورت ناقص برای استنتاج عددی ارائه نمی‌شود؛ عنوان و توضیح با پرچم `content_complete=False` می‌آید و اصل جدول در نمایشگر در دسترس است. کادر کامل جدول ساختار سلول‌های ادغام‌شده را حفظ می‌کند. بررسی نهایی برای درخواست صرفاً رسانه‌ای، وجود رسانه در ارجاع‌های منتخب را لازم می‌داند.

endpoint نمایش اصل رسانه:

```text
GET /api/v1/uptodate/topics/{id}/media/{key}/?content_hash=...&graphic_hash=...
```

کلید متعلق به مقاله و هش نسخهٔ مقاله/گرافیک بررسی می‌شوند؛ تغییر منبع ۴۰۹ می‌دهد. HTML پاک‌سازی می‌شود و تصویر از بایت‌های دیتابیس می‌آید. محتوای رسانه در کش پایدار اپ ذخیره نمی‌شود. کش پاسخ فعلی برای ارجاع‌های بدون anchor بند، از جمله رسانه، fail-closed است و پاسخ رسانه‌ای را به‌عنوان cache hit تأییدشده برنمی‌گرداند؛ کش پاسخ‌های معمول برقرار است.

وضعیت ساخت لوکال: **۲۱٬۲۷۳ از ۲۱٬۲۷۳ مقاله، ۹۰٬۵۹۹ مورد رسانه، صفر درخواست مدل/embedding**. نسل بردار فعال `73f89df9-d447-4cb7-a32c-f8296b81fa4b` و ۶۷۰٬۹۹۱ بردار قبلی باقی ماندند. یک جست‌وجوی مستقیم جدول شب‌ادراری پس از محدودسازی موضوع، در حدود ۰٫۴۳ ثانیه تنها جدول مرتبط مقالهٔ ۲۸۶۳ را انتخاب کرد؛ این زمان بازیابی رسانه است و زمان کامل مدل محسوب نمی‌شود.

## خروجی PDF

دکمهٔ PDF در خوانندهٔ UpToDate، فایل واقعی را از مسیر زیر می‌گیرد:

```text
GET /api/v1/uptodate/topics/{id}/pdf/
```

مجوز منبع لازم است و پاسخ `private,no-store` و attachment است. متن مقاله، جدول‌ها و گرافیک‌های محلی پیوندخورده با WeasyPrint روی سرور به A4 تبدیل می‌شوند. URL fetcher فقط شناسهٔ تصویر محلی شناخته‌شده را می‌پذیرد؛ فایل سیستم و منابع خارجی واکشی نمی‌شوند. وب با Blob دانلود می‌کند؛ native فایل موقت را با share sheet سیستم تحویل می‌دهد. درخواست بدون توکن در URL انجام می‌شود.

آزمون مقالهٔ واقعی ۲۸۶۳: PDF معتبر ۲۸ صفحه، حدود ۱۴۰ کیلوبایت و حدود ۴٫۷۵ ثانیه برای تولید، همراه گرافیک‌ها. این نمونه تضمین زمان تمام مقاله‌ها نیست. نمایش صفحهٔ اول نیز بررسی شد.

## ورود با OTP ایمیلی

`EmailOtpForm` از صفحهٔ ورود/ثبت‌نام در دسترس است. کد برای ایمیل کوچک‌حرف‌شده ارسال می‌شود؛ پاسخ API کد را برنمی‌گرداند. حساب جدید فقط پس از تأیید کد ساخته می‌شود؛ ایمیل موجود به همان حساب وارد می‌شود. حساب غیرفعال پذیرفته نمی‌شود و حساب تازه مسیر تنظیم رمز و تکمیل پروفایل فعلی را ادامه می‌دهد.

`EmailLoginIdentity` قفل پایدار هر ایمیل و زمان تأیید را نگه می‌دارد. `EmailOneTimeCode` فقط HMAC کد، انقضا، تلاش و وضعیت مصرف را ذخیره می‌کند. آخرین کد معتبر است؛ پنج تلاش اشتباه و انقضا جلوی ورود را می‌گیرند. cooldown، سقف ارسال و محدودیت IP از تنظیم‌های فعلی OTP گرفته می‌شوند. SMTP خطای عمومی می‌دهد و کد/رمز در لاگ چاپ نمی‌شوند. backend کنسول/فایل برای کد ورود رد می‌شود؛ آزمون‌ها از locmem استفاده می‌کنند.

```text
POST /api/v1/auth/email-otp/request/  {email}
POST /api/v1/auth/email-otp/verify/   {email,code,device_name?}
```

ارسال مستقیم با timeout انجام می‌شود و وابسته به صف جست‌وجو نیست. احراز موفق همان نشست و قانون جایگزینی نشست قبلی را استفاده می‌کند.

## تنظیم سرور و انتشار

۱. کد و dependencyهای جدید backend را منتشر کنید. Dockerfile کتابخانه‌های Pango و فونت DejaVu را نصب و در build یک PDF آزمایشی تولید می‌کند. برای نصب بدون Docker، کتابخانه‌های متناظر سیستم‌عامل نیز لازم‌اند.

۲. در مسیر `backend` و با تنظیم‌های درست همان سرور اجرا کنید:

```bash
python manage.py migrate
python manage.py migrate --database reference_search
python manage.py build_reference_media --workers 2
python manage.py build_reference_media --status
```

ساخت رسانه به نسل فعال و آمادهٔ جست‌وجوی hybrid و مسیر صحیح فایل‌های UpToDate نیاز دارد؛ تنظیم دیتابیس/منبع در [سند ۳۹](39-smart-search-status-deployment.fa.md) است. قطع اجرای ساخت با تکرار همان دستور ادامه پیدا می‌کند. `--rebuild` فقط هنگام نیاز به ساخت دوبارهٔ این فهرست استفاده شود. بردارسازی API و HNSW دوباره لازم نیستند. جدول‌های اصلی و ایندکس باید قبلاً روی سرور مستقر باشند؛ وجود کد به‌تنهایی دادهٔ لوکال را منتقل نمی‌کند.

۳. SMTP را در رازهای محیط سرور تنظیم کنید؛ مقادیر زیر جای‌نگهدار هستند:

```dotenv
AUTH_EMAIL_OTP_ENABLED=True
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=<smtp-host>
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_USE_SSL=False
EMAIL_HOST_USER=<mailbox-user>
EMAIL_HOST_PASSWORD=<secret>
DEFAULT_FROM_EMAIL=<verified-sender>
EMAIL_TIMEOUT=10
EMAIL_OTP_CODE_LENGTH=6
EMAIL_OTP_TTL_SECONDS=300
```

می‌توان به‌جای مقادیر SMTP از `EMAIL_CREDENTIALS_FILE` استفاده کرد: JSON با همان کلیدهای مجاز، خارج از گیت/ایمیج و با مجوز فایل `600`. تنظیم صریح محیط اولویت دارد. فایل خصوصی لوکال `backend/.private/email.json` است؛ محتوای فایل اصلی مالک در مستندات یا کد کپی نمی‌شود. تنظیم SMTP لوکال در سرور خودکار موجود نیست و باید به‌صورت راز مستقر شود.

۴. API و worker جست‌وجو را با نسخهٔ جدید راه‌اندازی کنید. وب را با `npm run build:web` بسازید؛ این دستور کش Metro را پاک می‌کند تا آدرس API آزمایشی از export قبلی وارد انتشار نشود. برای اندروید ساخت native جدید بگیرید؛ `expo-sharing` و پلاگین آن اضافه شده‌اند و نصب اپ قبلی ممکن است این ماژول را نداشته باشد. کارکرد روی دستگاه اندرویدی در این نوبت آزمایش نشده است.

۵. در «مدیریت ← اپ ← اعتبار سرچ هوشمند» بسته‌های ۱۰۰/۵۰۰/۱۰۰۰، تعرفه و درگاه واقعی را بررسی کنید. دکمهٔ TGJU نرخ و قیمت فروش بعدی را تغییر می‌دهد؛ مبلغ سفارش قبلاً ساخته‌شده و اعتبار قبلاً خریداری‌شده تغییر نمی‌کنند. درگاه لوکال آزمایشی است.

## مرز اعتبارسنجی

آزمون‌های ورود ایمیلی، کنترل دسترسی و هش رسانه، پاک‌سازی HTML، تولید PDF، تصویر داخل جدول، انتخاب نوع/موضوع رسانه، clone نسل جست‌وجو، کیف اعتبار، billing و تنظیم‌ها پاس شدند. TypeScript، ساخت وب و بررسی migration نیز موفق بودند. آزمون مرورگر با دادهٔ نمونه، پخش نتایج و نمایش جدول/تصویر، پاسخ انتهایی، کیف و خرید، مسیر بالینی/پرکاربردها و فرم ایمیل را بدون هزینهٔ مدل بررسی کرد؛ دانلود PDF مقالهٔ واقعی نیز از داخل همان مرورگر تأیید شد. ارسال ایمیل واقعی با تأیید دریافت مالک انجام شد. در بررسی فایل‌های قابل انتشار، کلید API یا رمز SMTP یافت نشد.

تلاش واقعی اتصال سرچ رسانه‌ای به مدل، پیش از اجرای جست‌وجو با `PROVIDER_UNAVAILABLE` متوقف شد؛ بررسی مستقیم ایندکس و نمایشگر موفق بود. این وضعیت به معنی تأیید پاسخ کامل مدل یا تضمین زیر ۲۰ ثانیه نیست. برای ارزیابی بالینی، پس از در دسترس بودن ارائه‌دهنده چند پرسش واقعی جدول/تصویر باید توسط مالک بازبینی شوند.
