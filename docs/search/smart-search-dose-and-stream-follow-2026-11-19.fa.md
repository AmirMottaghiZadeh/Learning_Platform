# اصلاح دوزِ همراه دارودرمانی و نمایش پاسخ استریم

تاریخ محلی: ۱۹ نوامبر ۲۰۲۶. مبنا: کامیت `58271db`. سؤال واقعی مالک: «دارودرمانی صرع میوکلونیک چیست و با چه دوزی؟».

## علت جاافتادن دوز

این سؤال با API واقعی و مدل و embedding فعلی بازتولید شد. مقالهٔ بیماری، داروی توصیه‌شده را داشت؛ اما شواهد ورودی نویسنده از بعضی داروهای دیگر، حتی داروهای ذکرشده در بخش «پرهیز»، پر می‌شدند و رژیم داروی مرتبط جا می‌افتاد.

اشکالات کد:

- `regimen_supplements` پیش از یافتن متن قابل استفاده، شناسهٔ نامزد را در شش ظرفیت related ثبت می‌کرد. lookupهای ناموفق می‌توانستند راهِ لینک واقعی منبع را ببندند.
- عبارت بلند سؤال به‌صورت AND در یک پاراگراف مونوگراف الزام می‌شد. یک زیرنوع بیماری الزاماً در برچسب اندیکاسیونِ مونوگراف تکرار نشده است؛ نام بخش دوز می‌تواند عمومی‌تر و در label جدا از پاراگراف عددی باشد.
- اولین اشاره به یک دارو در بخش «جایگزین‌ها» می‌توانست بر بخش اختصاصی همان دارو مقدم شود. dedup و visited نیز بعد از lookup ناموفق، فرصت استفاده از بافت بهترِ همان لینک را می‌گرفتند.
- امتیاز label به کلماتی مانند «اثربخشی» و «تثبیت‌شده» حساس بود. در مورد واقعی، این عبارت‌های عمومی می‌توانستند label یک اندیکاسیون دیگر را بر label تشنج مقدم کنند.
- در تکمیل محلیِ دوز، `intent` همچنان دارودرمانی باقی می‌ماند. تشخیص وجود رژیم نیز صرف دیدن یک عدد با واحد در تمام شواهد بود.

اصلاح‌ها:

1. ثبت ظرفیت related پس از رسیدن به نامزد واقعاً قابل استفاده؛ مقصدهای خوانده‌نشده یا ناموفق ظرفیت تازه مصرف نمی‌کنند.
2. متن اصلی بخش «داروهایی که باید از آن‌ها پرهیز شود» حفظ می‌شود، ولی دوز همان داروها برای یک سؤال معمولِ دارودرمانی واکشی نمی‌شود.
3. بخش اختصاصی دارو و بافت توصیهٔ منبع در پیوندها اولویت دارند. برای لینک ناموفق، حداکثر یک بافت دیگر از همان منبع امتحان می‌شود؛ جست‌وجوی سراسری تازه ساخته نمی‌شود.
4. در نبود تطبیق کامل نام زیرنوع، فقط labelهای اصلیِ مونوگراف پیوندخورده با واژه‌های همان پاراگراف والد و مفاهیم سؤال سنجیده می‌شوند. عنوان ارجاع انتهای پاراگراف و عبارت‌های عمومی کیفیت شواهد، سیگنال اندیکاسیون محسوب نمی‌شوند. متن، label، محدودیت و رابطهٔ والد بدون بازنویسی به نویسنده/بازبین می‌رسند؛ نگاشت پزشکیِ حدسی ساخته نمی‌شود.
5. تکمیلِ جنبهٔ مفقودِ دوز با `intent=dose` در همان دامنه و همان پروفایل سؤال انجام می‌شود. عددِ صرفِ غلظت فرآورده به‌تنهایی رژیم درمان محسوب نمی‌شود.

## نتیجهٔ مثال واقعی و حدود آن

پیش از اصلاح، پوشش `drug_regimen` مفقود بود و پاسخ می‌گفت دوز در منابع موجود نیست. پس از اصلاح، دوزِ منبع مرتبط وارد پاسخ شد و بازبین برای `drug_regimen` وضعیت supported ثبت کرد. بررسی محلی بدون API نیز خوانده‌شدن بخش `Dosing: Adult` از مونوگراف داروی اصلی را تأیید کرد.

**این نتیجه تأیید کامل بالینی یا همهٔ اجزای جواب نیست.** اجرای نهایی همان سؤال همچنان partial بود: دوز پشتیبانی‌شده باقی ماند، ولی بازبین بخش انتخاب درمان را کامل نپذیرفت. دوزِ یک اندیکاسیون/جمعیت دیگر به‌زور پاسخ کامل نمی‌شود و verifier ضعیف یا حذف نشده است. ورودی/خروجی اجرای واقعی در فایل‌های `0600` زیر `backend/.private/myoclonic-dose-*.json` نگه داشته شده و در Git قرار نمی‌گیرد.

تعداد تماس معمول افزایش نکرد: تحلیل، نویسنده و بازبین به‌اضافهٔ یک embedding اولیه. آماده‌سازی دوبارهٔ embedding یا HNSW لازم نیست.

## نمایش بولد و دنبال‌کردن پاسخ

- `ReferenceAnswerText` نشانه‌های `**` را به متن معمولی و متن دارای فونت ۷۰۰ تبدیل می‌کند؛ HTML اجرا نمی‌شود و متن/اعداد پزشکی بازنویسی نمی‌شوند. نسخهٔ نهایی و پیش‌نویس از یک renderer استفاده می‌کنند. بخش بولدِ هنوز بسته‌نشده در استریم هم خوانا می‌ماند.
- اسکرول به انتهای صفحه/منابع حذف و موقعیت دنبالهٔ کادر پاسخ هدف شده است. اضافه‌شدن کارت‌های منابع پایین صفحه، کاربر را از متن در حال تولید دور نمی‌کند.
- اسکرول دستی، دنبال‌کردن خودکار را متوقف می‌کند؛ دکمهٔ «دنبال‌کردن پاسخ» آن را از سر می‌گیرد. پایان پاسخ نیز صفحه را ناگهان به کارت رسانه نمی‌برد.
- skeleton فقط تا رسیدن اولین متن نمایش داده می‌شود. پس از آن متن استریم و وضعیت «در حال نوشتن پاسخ» یا «در حال بررسی پاسخ»، همراه امکان توقف، در همان کادر باقی می‌مانند.
- بازیابی job، پیش‌نویس و قابلیت لغو آن را نیز برمی‌گرداند.

## آزمون و استقرار

مجموعهٔ ۳۱۶ تست مرتبط بک‌اند گذشت؛ سپس آزمون‌های متمرکز پیوند/رژیم برای اصلاح امتیاز label اجرا شدند. TypeScript و export وب موفق بودند. چهار آزمون parser/هندسه و آزمون مرورگر واقعی در اندازه‌های ۳۹۰×۸۴۴ و ۱۲۸۰×۹۰۰ گذشتند: بولد، دیدن دنبالهٔ پاسخ با منابع بلند در پایین، اسکرول دستی، ادامهٔ دنبال‌کردن و متن نهایی بررسی شدند. مرورگر از API و حساب کاملاً ساختگی استفاده می‌کند؛ به دیتابیس یا مدل واقعی وصل نمی‌شود.

```bash
cd frontend
npm run typecheck
npm run build:web
npm run test:reference-answer
npm run test:reference-answer:browser
```

تست مرورگر از web export موجود و Chrome نصب‌شده استفاده می‌کند؛ تصاویر زیر `backend/exports/reference-answer-ui/` خروجی محلیِ نادیده‌گرفته‌شده‌اند. برای این تغییر migration، متغیر محیطی جدید یا ساخت دوبارهٔ ایندکس لازم نیست؛ بک‌اند و خروجی جدید فرانت‌اند باید هر دو منتشر شوند.
