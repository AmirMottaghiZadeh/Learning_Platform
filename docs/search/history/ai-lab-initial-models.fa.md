# آرشیو آزمایش اولیهٔ مدل‌ها

این سند سابقهٔ Jev/GLM و بازیابی چندمنبعی است و تنظیمات اجرایی فعلی نیست. مدل‌ها و منابع فعلی در [سند ۲۵](../../25-reference-chat-lab.fa.md) هستند.

# محیط آزمایشی پرسش از منابع برنامه

تاریخ بررسی: ۲۰۲۶-۱۱-۱۰. این قابلیت یک چت آنلاین آزمایشی در خانهٔ اپ است. ورودی آن پرسش فارسی، مدل منتخب و منابع منتخب است؛ خروجی، توضیح کوتاه فارسی، نقل‌قول قابل تطبیق با داده و دکمهٔ باز کردن منبع در اپ است. کیفیت پاسخ‌ها هنوز نیازمند ارزیابی انسانی است؛ تطبیق ماشینی تضمین صحت پزشکی یا کامل بودن پاسخ نیست.

## مدل‌ها و نتیجهٔ اتصال

| انتخاب | مسیر گپ‌جی‌پی‌تی | نقش |
|---|---|---|
| Jev 1.14 | `POST https://api.gapgpt.app/v1/systemone` | تشخیص درخواست مرجع پزشکی و امتیازدهی ارتباط بندهای بازیابی‌شده؛ فهم پرسش و توضیح فارسی در این حالت با GLM انجام می‌شود |
| GLM-4 Flash | `POST https://api.gapgpt.app/v1/chat/completions` | تبدیل پرسش به عبارت جست‌وجو و توضیح فارسی؛ بررسی مستقل ارتباط منبع و وفاداری توضیح با Jev انجام می‌شود |

مسیر Chat Completions برای `typesafe/jev-1.14` در آزمایش اولیه HTTP 500 و پیام عدم پشتیبانی درخواست چت داد. پس از استفاده از مسیر بومی، پاسخ معتبر دریافت شد؛ مدل گزارش‌شده `typesafe/jev-1.14-20261014` بود. برای GLM، مدل گزارش‌شده `glm-4-flash` بود. کد هیچ مدلی را بی‌اطلاع کاربر جایگزین نمی‌کند و شناسهٔ گزارش‌شدهٔ ارائه‌دهنده را در metadata نگه می‌دارد.

Jev مدل تصمیم‌گیری است؛ توضیح فارسی به نام Jevِ مستقل معرفی نمی‌شود. قرارداد بومی `state` و `questions` و مقدار `noul` مطابق [مرجع رسمی TypeSafe](https://docs.typesafe.ai/api/system-one) است. این مرجع، پشتیبانی تمام درگاه‌های واسط را تضمین نمی‌کند؛ اتصال گپ‌جی‌پی‌تی جداگانه آزمایش شده است.

## راه‌اندازی محلی

در `backend/.env`، فقط روی محیطی که باید آزمایش در آن فعال باشد:

```dotenv
AI_LAB_ENABLED=True
AI_LAB_BASE_URL=https://api.gapgpt.app/v1
AI_LAB_JEV_TRANSPORT=systemone
AI_LAB_TIMEOUT_SECONDS=90
AI_LAB_CREDENTIALS_FILE=/home/amir/Desktop/api_key_gapgpt
AI_LAB_USER_IDS=
```

فایل اعتبارنامه باید مجوز `600` داشته باشد؛ هر کلید در خط پس از برچسب حاوی `jev` یا `glm` قرار می‌گیرد. مقدار هیچ کلیدی در این سند، فرانت‌اند یا مخزن قرار نمی‌گیرد. همین تنظیم‌های غیرمحرمانه در `.env` محلی این دستگاه اعمال شده‌اند. پس از تغییر تنظیم‌ها، بک‌اند را دوباره اجرا کنید:

```bash
cd backend
.venv/bin/python manage.py runserver 127.0.0.1:8000
```

فرانت‌اند طبق [راه‌اندازی محلی](../../02-local-setup.md) به همین API متصل شود. پس از ورود با سوپریوزر یا نقش فعال `platform_admin`، گزینهٔ «آزمایش پرسش از منابع» در خانه نمایش داده می‌شود. برای کاربران آزمایشی عادی، شناسه‌ها را با کاما در `AI_LAB_USER_IDS` وارد کنید؛ مجوز منابع و محدودیت اشتراک آن‌ها همچنان اعمال می‌شود. `is_staff` به‌تنهایی مجوز این آزمایش نیست.

برای تحویل این کار، یک اجرای محلی وب روی `http://127.0.0.1:8082` با API روی `127.0.0.1:8002` نیز راه‌اندازی شد. این اجرای نهایی از تنظیمات و دیتابیس توسعهٔ فعلی استفاده می‌کند؛ با حساب موجود پروژه وارد شوید. اجرای فرایندها موقتی است و انتشار روی سرور انجام نشده است. بعد از خاموش شدن آن‌ها، راه‌اندازی معمول بالا کافی است؛ پورت API ساخت وب باید با API اجراشده یکسان باشد.

## فعال کردن روی سرور

پیش‌فرض کد `AI_LAB_ENABLED=False` است. روی سرور فقط هنگام آماده بودن منابع و اعتبارنامه‌ها آن را روشن کنید. برای کلیدها از متغیرهای محرمانهٔ سرویس استفاده کنید:

```dotenv
AI_LAB_ENABLED=True
AI_LAB_BASE_URL=https://api.gapgpt.app/v1
AI_LAB_JEV_TRANSPORT=systemone
AI_LAB_CREDENTIALS_FILE=
AI_LAB_JEV_API_KEY=
AI_LAB_GLM_API_KEY=
AI_LAB_USER_IDS=
```

دو مقدار خالی کلید را در پنل محرمانهٔ میزبان وارد کنید؛ این نمونه عمداً فاقد مقدار است. مسیر Desktop لپ‌تاپ روی سرور وجود ندارد. راه دیگر mount فایل خصوصی با مجوز `600` و تنظیم `AI_LAB_CREDENTIALS_FILE` روی مسیر همان فایل در کانتینر است. کلیدهای محیطی بر فایل اولویت دارند. از متغیرهای `EXPO_PUBLIC_*` برای هیچ کلیدی استفاده نکنید.

بک‌اند و فرانت‌اند جدید هر دو باید منتشر شوند؛ migration یا نصب SDK تازه‌ای برای این قابلیت لازم نیست. فایل‌های `.private/` از build context هر دو Dockerignore حذف شده‌اند. در اجرای چند worker یا چند replica، کش `throttle` باید واقعاً مشترک، مانند Redis، باشد؛ `LocMemCache` فقط برای آزمایش تک‌پردازهٔ محلی مناسب است.

## جریان درخواست و مرز داده

`DashboardScreen` → `AiLabScreen` → `api/aiLab.ts` → `ai_lab/views.py` → `services.py` → `retrieval.py` → منابع موجود؛ سپس `provider.py` مدل را صدا می‌زند. مدل نه SQL می‌سازد، نه ابزار مرور وب دارد و نه نشانی دلخواهی برای منبع تولید می‌کند.

| منبع | دادهٔ خوانده‌شده | ارجاع در اپ |
|---|---|---|
| UpToDate | جست‌وجوی فعال فعلی شامل tagging؛ سپس بندهای مقاله از همان snapshot | مقاله، بخش، شناسهٔ بند و هش محتوا |
| دارونامه | بخش‌های منتشرشدهٔ `IngredientProfileSection`؛ پیش‌نویس مرکز کیفیت داده خوانده نمی‌شود | جزئیات همان دارو |
| Medscape | متن، فهرست و جدول بخش‌های مقاله | مقاله و مسیر بخش |
| Lexicomp | خلاصه و مدیریت بالینی تداخلِ دو نام دقیق و بی‌ابهام | همان دو داروی ازپیش‌انتخاب‌شده در صفحهٔ تداخلات |
| ماشین‌حساب | توضیح و متن مرجع ماشین‌حساب | صفحهٔ همان ماشین‌حساب؛ مدل فرمول محاسباتی اجرا نمی‌کند |

بازیابی محدود است: حداکثر دو عبارت برای هر بخش، چهار نتیجهٔ UpToDate برای هر عبارت و حداکثر ۲۴ بند نهایی. ابتدا از مقاله‌ها و منابع مختلف بند انتخاب می‌شود، سپس تا سه بند هر مقاله بررسی می‌شود؛ یک مقاله نمی‌تواند همهٔ ظرفیت را اشغال کند. پردازش متن در دسته‌های شش‌تایی انجام می‌شود و محدودیت سابق سه ارجاع حذف شده است. تمام ارجاع‌های مرتبط و تأییدشدهٔ این دسته‌ها نگه داشته می‌شوند. تعداد متن‌های واقعاً بررسی‌شده و محدود بودن پوشش در پاسخ و رابط مشخص است. این پایلوت تضمین یافتن همهٔ پاسخ‌های موجود در کل دیتابیس نیست. اطلاعات بیرونی، PubChem زنده، چت پشتیبانی و داده‌های شخصی کاربران منبع پاسخ نیستند.

بازبینی پس از گزارش خطا: جست‌وجوی دارونامه ابتدا فقط نام فارسی/انگلیسی دارو را تطبیق می‌داد و سؤال مبتنی بر نام بیماری را از متن کاربردها پیدا نمی‌کرد. تطبیق متن بالینی منتشرشده، شامل خلاصه‌ها، متن مرجع و اطلاعات سایر منابع، اضافه شد؛ تطبیق نام دارو اولویت دارد. این تغییر در آداپتور چت است و جست‌وجوی فعلی اپ را تغییر نمی‌دهد. در بررسی مستقیم با عبارت `nocturnal enuresis`، آداپتور UpToDate از چهار مقاله ۵۵۸ بند اولیه خواند و مقالهٔ مدیریت شب‌ادراری کودکان را در نتایج برتر داشت؛ برای `psoriasis`، ۴۶۵ بند UpToDate و ۳۲۵ بند Medscape خوانده شد. این بررسی صرفاً خواندن دیتابیس و رتبه‌بندی را ثابت می‌کند؛ تأیید پاسخ مدل را ثابت نمی‌کند.

در همین بررسی مشخص شد عنوان موجود در Medscape، `Enuresis` است و تطبیق الزامی تمام واژه‌های `nocturnal enuresis` آن را حذف می‌کرد. در نبود تطبیق کامل عنوان، بازیابی محدود بر اساس واژه‌های مشترک عنوان اضافه شد؛ نتایج بر اساس تعداد واژهٔ مشترک مرتب و همچنان به پنج مقاله محدود می‌شوند. گسترش عنوان ممکن است دقت را کم کند؛ تأیید سؤال و نقل‌قول همچنان لازم است. پس از اصلاح دارونامه، همان عبارت از متن‌های بالینی نیز نتیجه داد؛ نبود تطبیق نام دارو دیگر به معنی نبود محتوای دارویی فرض نمی‌شود.

تکرار بررسی بدون فراخوانی مدل با همان عبارت، ۴۳ بخش دارونامه و ۳۷۲ بند اولیهٔ Medscape برگرداند؛ این تعداد، نامزدهای پیش از رتبه‌بندی و محدودسازی نهایی است. مدل همچنان فقط بندهای منتخب را می‌بیند، نه همهٔ رکوردهای دیتابیس. این نسخه بازیابی یک‌مرحله‌ای دارد و عامل خودکار چندمرحله‌ای با بازنویسی و تکرار جست‌وجو نیست.

سؤال به حداکثر سه بخش صریح با علامت سؤال، سمی‌کالن، خط جدید یا اتصال «و خط …» تقسیم می‌شود. متن سؤال کاربر حفظ می‌شود؛ مدل حق افزودن سؤال تازه ندارد. این محیط جست‌وجوی مرجع است: نبود سن دقیق، شدت یا سابقهٔ درمان مانع جست‌وجوی موضوع شناسایی‌شده نمی‌شود. درخواست جزئیات از سوی برنامه‌ریز نادیده گرفته و در صورت فقدان عبارت، برنامهٔ جست‌وجو یک‌بار دوباره ساخته می‌شود. تفاوت‌های جمعیت و شرایط درمان از خود منابع بیان می‌شوند؛ اسکیزوفرنی از واژهٔ سایکوتیک فرض نمی‌شود. پرسش کودک از عنوانی که صریحاً مخصوص بزرگسالان است پاسخ نمی‌گیرد.

تنها شناسه‌های ساخته‌شده توسط بک‌اند قابل استنادند. متن اصلی از خود بند منبع در سرور ضمیمه می‌شود؛ مدل موظف نیست آن را دوباره کپی کند. اگر مدل نقل‌قول جداگانه بدهد، باید عیناً در بند اصلی باشد؛ شناسهٔ ناشناخته یا نقل‌قول تغییریافته حذف می‌شود. پس از بررسی GLM، Jev دو معیار مستقل می‌سنجد: پاسخ‌گویی منبع به جنبهٔ خواسته‌شدهٔ سؤال با آستانهٔ `0.75` و وفاداری همهٔ ادعاهای توضیح به نقل‌قول با آستانهٔ `0.85`. تعریف، شیوع یا علت بیماری به‌تنهایی پاسخ دارودرمانی محسوب نمی‌شود. منبع مرتبطی که توضیحش غلط یا حذف شده باشد، یک‌بار به‌تنهایی برای ترجمه به GLM داده و دوباره با Jev بررسی می‌شود. این آستانه‌ها آزمایشی‌اند و تضمین صحت پزشکی نیستند. هر دو مسیر انتخاب مدل برای این کنترل مستقل به کلید Jev نیاز دارند؛ نقش آن در رابط و `stages` مشخص است.

`overview_fa` از یک یا دو توضیح تأییدشده ساخته و پیش از ارجاع‌ها نمایش داده می‌شود؛ واقعیت پزشکی تازه‌ای در این مرحله تولید نمی‌شود. `retrieval` شمار نامزدها، مقاله‌ها، متن‌های منتخب و بررسی‌شده و پرچم `limited` را دارد. در خطای یک دسته، نتایج تأییدشدهٔ قبلی با هشدار ناقص بودن حفظ می‌شوند.

## قرارداد API

تمام مسیرها زیر `/api/v1/` و نیازمند ورود هستند:

| روش و مسیر | کاربرد |
|---|---|
| `GET ai-lab/status/` | `enabled`، شناسهٔ مدل‌ها و منابع؛ فاقد کلید و مسیر فایل |
| `GET ai-lab/active/` | بازیابی درخواست فعال همان حساب، شامل شناسه، سؤال، مدل، منابع و مرحله؛ بدون شروع درخواست تازه |
| `POST ai-lab/ask/` | ساخت آزمایش؛ پاسخ `202 {job_id}` |
| `GET ai-lab/results/<uuid>/` | وضعیت همان حساب: `running` با `stage`، `complete` با `result` یا `failed` با خطای پاک‌سازی‌شده |

نمونهٔ بدنهٔ درخواست:

```json
{
  "question": "دارودرمانی شب ادراری در کودکان چیست؟",
  "model": "jev",
  "sources": ["uptodate", "medscape"],
  "history": []
}
```

`model` فقط `jev` یا `glm` است. سؤال ۳ تا ۱۵۰۰ نویسه، تاریخچه حداکثر چهار سؤال و منابع یک تا پنج عضو از فهرست ثابت هستند. URL منبع، ابزار یا دستور SQL از کلاینت پذیرفته نمی‌شود. هر بخش خروجی وضعیت، سؤال، عبارت‌های جست‌وجو، نقل‌قول‌ها، توضیح‌ها و target معتبر اپ دارد. `stages` مدل درخواستی و گزارش‌شده، زمان و مصرف توکن گزارش‌شده را نگه می‌دارد؛ توکن‌ها قیمت یا مبلغ صورتحساب نیستند.

مصرف ثبت‌شده مربوط به مراحل موفق است؛ درخواست ناموفق یا تلاش دوباره برای قالب JSON ممکن است مصرف اضافه داشته باشد که در این جمع دیده نشود. صورتحساب واقعی را از پنل ارائه‌دهنده بررسی کنید.

## حریم خصوصی و محدودیت اجرا

- سؤال و گزیدهٔ منابع برای پردازش به گپ‌جی‌پی‌تی ارسال می‌شوند؛ متن این موضوع در محیط چت آمده است. اطلاعات شناسایی بیمار نباید به پرسش افزوده شود.
- هیچ کلیدی به وب‌اپ/APK فرستاده نمی‌شود. redirect درخواست دارای اعتبارنامه دنبال نمی‌شود؛ پاسخ حاوی کلید رد می‌شود؛ بدنهٔ خطای ارائه‌دهنده در API یا لاگ نوشته نمی‌شود.
- سؤال حاوی الگوی کلید API رد می‌شود. گفتگو در Zustand فقط در حافظه نگه‌داری و با خروج یا عوض شدن حساب پاک می‌شود؛ در localStorage، AsyncStorage یا کش query ذخیره نمی‌شود.
- سؤال، مدل، منابع منتخب و نتایج شغل در کش بک‌اند تا ۱۵ دقیقه نگه‌داری می‌شوند؛ تاریخچهٔ سؤال‌ها در آن ذخیره نمی‌شود. نتیجهٔ حساب دیگر `404` است. پاسخ‌های API `private, no-store` هستند. اطلاعات بازیابی مستقیم دریافت می‌شود و وارد کش پایدار React Query نمی‌شود. زمان polling اعتبار نتیجه را تمدید نمی‌کند.
- یک درخواست فعال برای هر حساب، دو جایگاه فعال مشترک و ۲۰ آزمایش در ساعت برای هر حساب وجود دارد. هر آزمایش می‌تواند چند فراخوانی مدل داشته باشد؛ این سقف تعداد درخواست است، نه سقف ریالی.
- هر درخواست upstream حداکثر ۹۰ ثانیه و بودجهٔ زمانی مدل برای کل آزمایش ۹ دقیقه است. JSON نامعتبر حداکثر یک‌بار دوباره درخواست می‌شود. در خطای ارائه‌دهنده، متن پزشکی حدس زده نمی‌شود.
- اجرای پس‌زمینه در threadهای محدود وب‌سرور است؛ صف پایدار Celery نیست. worker هر ۱۰ ثانیه علامت زنده بودن ثبت می‌کند. درخواست فاقد heartbeat بیش از ۴۵ ثانیه، فاقد رکورد، خاتمه‌یافته یا قدیمی‌تر از ۱۰ دقیقه، قفل باقی‌مانده را آزاد می‌کند. `EXPERIMENT_EXPIRED` برای اجرای قطع‌شده ثبت می‌شود؛ worker قدیمی نمی‌تواند آن را دوباره running کند.
- با باز کردن دوباره صفحه یا refresh، درخواست واقعاً فعال بازیابی و polling آن ادامه داده می‌شود. `AI_LAB_BUSY` حاوی شناسهٔ درخواست قبلی همان حساب است؛ اپ به‌جای ساخت درخواست تکراری، آن را بازیابی می‌کند. محدودیت یک اجرای همزمان هر حساب برقرار است.
- رویدادهای `aiLab` در فهرست مجاز فعالیت اپ ثبت شده‌اند؛ صف‌های قبلی شامل این صفحه نیز پس از آپدیت بک‌اند پذیرفته می‌شوند. متن سؤال یا پاسخ در رویدادهای فعالیت ثبت نمی‌شود.

## آزمون و ارزیابی

سؤال‌های واقعی مالک پروژه برای مقایسه:

1. «دارودرمانی شب ادراری در کودکان چیست»
2. «خط اول درمان پسوریازیس و خط سوم درمان بیماران سایکوتیک»

در دورهای توسعه، GLM ابتدا ترجمهٔ اشتباه `nocturia` و بند نامرتبط بزرگسالان تولید کرد. کنترل تطابق با سؤال، فیلتر جمعیت، حفظ متن سؤال و رتبه‌بندی بخش درمان پس از مشاهدهٔ این خطا اصلاح شدند. در یک اجرای کامل، مسیر Jev+GLM مقالهٔ `Nocturnal enuresis in children: Management`، بخش `Suggested approach` و نقل‌قول معتبر آن را برگرداند؛ تکرار همان آزمایش گاهی به دلیل انتخاب یا تأیید مدل، نتیجه را کنار گذاشت. این نوسان باید در ارزیابی لحاظ شود؛ موفقیت یک نمونه به معنی آماده بودن پاسخ‌گویی بالینی عمومی نیست.

| نمونهٔ اجرای کامل در دور توسعه | نتیجه | زمان | توکن گزارش‌شدهٔ مراحل موفق |
|---|---|---|---|
| سؤال ۱، Jev+GLM | یک نقل‌قول از مقالهٔ مدیریت شب‌ادراری کودکان | ۳۸٫۲ ثانیه | ۳۰۵۲، مجموع هر دو مدل |
| سؤال ۲، Jev+GLM | خروجی قابل نمایش تأیید نشد | ۲۰٫۳ ثانیه | ۵۰۶۴، مجموع هر دو مدل |
| سؤال ۱، GLM | خروجی قابل نمایش تأیید نشد | ۲۶٫۴ ثانیه | ۱۶۳۰ |
| سؤال ۲، GLM | خروجی قابل نمایش تأیید نشد | ۳۰٫۴ ثانیه | ۳۳۳۰ |

این اعداد مربوط به یک دور مشخص در جریان اصلاحات‌اند، نه benchmark نسخهٔ نهایی یا میانگین عملکرد. در تکرار پس از حفظ قطعی بخش‌های سؤال، Jev برای سؤال ۱ بندها را رد کرد و برای سؤال ۲ درخواست روشن‌سازی برگشت؛ دو درخواست GLM پس از حدود ۸۲ ثانیه با `PROVIDER_UNAVAILABLE` پایان یافتند. درخواست بدون اعتبارنامه به میزبان گپ‌جی‌پی‌تی نیز timeout شد؛ بنابراین این دور آخر ارزیابی کیفیت GLM محسوب نمی‌شود و خطا صرفاً با تغییر prompt رفع نشده است.

آزمون‌های خودکار مجوز، مالکیت شغل، اعتبارنامه، redirect، مدل اشتباه، بودجهٔ منابع، حذف نقل‌قول ساختگی و جلوگیری از فرض تشخیص را پوشش می‌دهند. آزمون‌های موجود UpToDate و آفلاین نیز اجرا شدند. فایل‌های مسیر جست‌وجوی فعال و tagging بدون تغییر باقی مانده‌اند؛ چت جدید فقط از سرویس فعلی برای خواندن استفاده می‌کند.

رابط در مرورگر در عرض‌های ۳۹۰، ۷۶۸ و ۱۴۴۰، تم روشن و تیره، حالت انتظار و خطای واقعی upstream بررسی شد. هنگام قطعی upstream، نمایش نتیجه با بازپخش پاسخ واقعی ذخیره‌شدهٔ دور قبلی بررسی شد؛ این تست رابط، اجرای زندهٔ جدید مدل محسوب نمی‌شود. دکمهٔ منبع به مقالهٔ واقعی وصل شد، بند موردنظر را برجسته کرد و بازگشت به چت، گفتگو را حفظ کرد. هیچ کلید واقعی در source یا خروجی export فرانت‌اند پیدا نشد.

اعتبارسنجی نهایی: ۱۳۱ آزمون برای `ai_lab`، `uptodate`، `offline` و `lexicomp` موفق؛ TypeScript و export وب موفق؛ تولید schema بدون خطا با دو هشدار موجود در `progress/serializers.py`؛ migration تازه‌ای لازم نیست. هش ۳۵ فایل محافظت‌شدهٔ مسیر جست‌وجوی موجود با ابتدای کار یکسان بود.

پس از اصلاح بازیابی درخواست و ثبت فعالیت، آزمون‌های `activity` نیز به مجموعهٔ بررسی اضافه شدند. تست مرورگر با پاسخ‌های کنترل‌شده نشان داد refresh درخواست فعال را بدون POST دوباره بازیابی می‌کند، پاسخ busy به ادامهٔ درخواست قبلی تبدیل می‌شود، متن سؤال جدید حفظ می‌شود و batch مخلوط فعالیت شامل `aiLab` با `202` پذیرفته می‌شود.

اعتبارسنجی این اصلاحات: ۱۴۶ آزمون backend موفق؛ TypeScript و build وب موفق؛ بازیابی refresh، مدیریت busy و ثبت فعالیت مخلوط در مرورگر موفق. نام و متن سؤال‌ها در هیچ رویداد heatmap ثبت نمی‌شود.

### اصلاح رفتار پرسش‌های کامل و چند مرجع

پس از گزارش توقف سؤال «دارودرمانی شب ادراری در کودکان چیست» با درخواست سن، توقف برای جزئیات بیمار از جریان جست‌وجوی مرجع حذف شد. پیش‌فرض منابع چت اکنون UpToDate و Medscape است. محدودیت سه ارجاع برداشته شد، انتخاب بندها بین مقاله‌ها و منابع توزیع می‌شود و مقدمهٔ فارسی تأییدشده قبل از ارجاع‌ها نمایش داده می‌شود.

در آزمایش زندهٔ این اصلاح میانی، همین سؤال در ۵۵٫۸ ثانیه چهار ارجاع از هر دو منبع برگرداند؛ ۱۲ متن از چهار مقاله برای مدل انتخاب شده بود. بررسی انسانی نشان داد برخی توضیح‌ها تعریف یا علت بیماری را به بند درمان نسبت داده‌اند و بررسی خود GLM این خطا را نگرفته است. این خروجی به عنوان پاسخ صحیح ثبت نمی‌شود. به همین دلیل بررسی مستقل ارتباط با جنبهٔ سؤال و وفاداری فارسی با Jev، و ترجمهٔ مجدد تک‌منبعی برای موارد نامعتبر یا حذف‌شده اضافه شد. نام هر مدل و نقش این مرحله در رابط و metadata مشخص است؛ مدل انتخابی بی‌اطلاع کاربر عوض نمی‌شود.

پس از این تغییر، اتصال‌های آزمایشی ترجمه و بررسی مستقل، و حتی درخواست بدون اعتبارنامه به میزبان گپ‌جی‌پی‌تی timeout شدند. بنابراین کیفیت اجرای زندهٔ نهایی این مرحله هنوز تأیید نشده است؛ تست‌های کنترل‌شده جای این ارزیابی را نمی‌گیرند. در نبود بررسی معتبر، متن پزشکی تأییدنشده نمایش داده نمی‌شود. ارزیابی زنده باید پس از برقرار شدن اتصال تکرار شود.

برای آزمایش دستی: هر سؤال را با Jev اجرا کنید، سپس «همین سؤال با GLM» را بزنید؛ موضوع، گروه سنی، خط درمان، فارسی توضیح، متن اصلی و مقصد دکمهٔ منبع را جداگانه بررسی کنید. تست واحد مدل را mock می‌کند و جای آزمایش زنده را نمی‌گیرد. فایل ارزیابی حاوی متن منابع را بدون بررسی در Git یا لاگ عمومی قرار ندهید.
