## دامنه، روش و نتایج ممیزی

اسکریپت ممیزی (`audit_full_corpus.py`؛ مسیر آرشیوی) همهٔ `contentId`های یکتا، غیرتهی و دارای `type=1` در FTS را خوانده، هر محتوای مربوط را از SQLite فقط‌خواندنی باز کرده و ساختار HTML و استخراج را بررسی می‌کند. یک رجیستری SQLite خصوصی بیرون مخزن فقط شامل شناسهٔ مقاله، hash نسخه، شناسهٔ پاراگراف، نوع بلوک، شماره و شناسهٔ بخش ایجاد شد. فهرست شناسه‌های استثنا در JSONL خصوصی خارج مخزن است؛ متن رفرنس در مخزن یا گزارش ثبت نشده است.

نتیجهٔ آماری (`uptodate-full-audit-2026-10-28.json`؛ مسیر آرشیوی): ۲۲٬۲۱۷ شناسه؛ ۲۲٬۲۱۷ محتوای خوانا؛ ۲۲٬۲۱۱ مقاله با یک ریشهٔ مورد انتظار و ۲٬۳۵۶٬۷۵۲ بلوک استخراج‌شده (۱٬۹۶۵٬۶۳۲ پاراگراف، ۳۴۶٬۷۷۱ آیتم فهرست، ۴۴٬۳۴۹ ردیف جدول). هیچ خطای پردازش، محتوای مفقود، anchor تکراری یا مغایرت شمارش annotation گزارش نشد. شمارش parser به‌تنهایی معادل تأیید DOM همهٔ مقالات نیست.

۶ مقاله ریشهٔ `topicText` نداشتند؛ هر شش سند ساختار HTML کوتاه و متفاوت داشت. آزمون Chrome (`uptodate-missing-topic-browser-audit-2026-10-28.json`؛ مسیر آرشیوی) با استخراج کل HTML آن‌ها، روی ۵۴ مقصد، صفر مشکل در وجود/یکتایی/تگ/متن و شش اسکرول موفق گزارش کرد. نسخهٔ ورودی و فهرست IDهای آزمایش‌شده در گزارش مرورگر با digest مشخص شده‌اند. این کنترل ساختاری است، نه تأیید معنایی یا کامل‌بودن محتوا.

در حالت ریشهٔ معمول، ۲۰٬۶۹۰ بلوک فاقد شناسهٔ section بودند. ۱٬۳۸۹ مقاله جدول داشت؛ ۸۸۹ مقاله `colspan`، ۴۲۹ مقاله `rowspan` و ۵ مقاله جدول تو‌در‌تو داشتند؛ این گروه‌ها ممکن است همپوشانی داشته باشند. در ۲٬۴۹۹ مقاله ID تکراری در HTML اصلی وجود داشت. ۳٬۴۵۸ مقاله دست‌کم یک flag ثبت‌شده داشتند. این علامت‌ها اثبات خطا نیستند؛ جداول پیچیده، نگاشت سرستون، sectionهای مفقود، HTML تکراری و محتوای تصویری همچنان به بررسی معنایی/مرورگر نیاز دارند. شناسهٔ استخراج‌شده مستقل از ID اصلی HTML است. تصویرها و محتوای متنی داخل تصویر استخراج نشده‌اند.

## اجرای Elasticsearch


Docker daemon با مجوز کاربر در دسترس نبود و سرویس روی ۹۲۰۰ وجود نداشت. لایهٔ رسمی تصویر Docker Hub `library/elasticsearch:8.19.0` برای amd64 از manifest با digest `sha256:2c0d73b770cbffaf95169e12ad8e78d464319d5e2959df7224ce732b42c38f1a` دریافت و digest لایه تأیید شد؛ runtime خارج مخزن استخراج شد. Elasticsearch 8.19.0 تک‌گره با heap ۵۱۲ MiB، بدون replica، روی loopback و برای آزمایش اجرا شد. این نسخه، انتخاب آزمایشی محیط است، نه توصیه یا تصمیم نسخهٔ نهایی. امنیت Elasticsearch در این اجرای موقت خاموش بود؛ پس از آزمون، سرویس متوقف شد. فایل‌های داده و runtime در مسیر خصوصی `/home/amir/.local/share/uptodate-search-audit/` مانده‌اند و نباید در مخزن یا سرویس عمومی قرار گیرند. برای استفادهٔ مداوم، احراز هویت، TLS، کنترل دسترسی محلی و تنظیمات عملیاتی باید برقرار شوند.

ایمپورت متنی (`index_lexical_corpus.py`؛ مسیر آرشیوی) یک سند Elasticsearch برای هر بلوک با `_id` برابر `paragraph_id` ساخت؛ متن، عنوان، بخش، سرستون جدول، نسخه و flag بررسی ذخیره شده‌اند. پیش از ورود، محتوا، تعداد و شناسه‌های هر مقاله با رجیستری مطبیق داده شد. ایندکس `uptodate-lexical-20261028-v1` جدا و بدون اتصال به مسیر محصول ساخته شد. گزارش مرحلهٔ اصلی (`uptodate-lexical-index-2026-10-28.json`؛ مسیر آرشیوی): ۲۲٬۲۱۱ مقاله و ۲٬۳۵۶٬۷۵۲ سند در ۷۳۲ ثانیه. سپس ایمپورت استثنا (`index_missing_topic_fallback.py`؛ مسیر آرشیوی) با کنترل digest نسخهٔ آزمون مرورگر، ۶ مقاله و ۵۴ بلوک را با flagهای `missing_topic` و `fallback_whole_html` افزود و رجیستری را کامل کرد: گزارش (`uptodate-fallback-index-2026-10-28.json`؛ مسیر آرشیوی).

**نتیجهٔ نهایی:** ۲۲٬۲۱۷ مقاله و ۲٬۳۵۶٬۸۰۶ سند بلوکی؛ شمارش سندهای Elasticsearch و رجیستری برابر است. بررسی composite aggregation روی همهٔ مقاله‌ها، صفر مقالهٔ گم‌شده و صفر مغایرت تعداد بلوک در هر مقاله نشان داد: نتیجه (`uptodate-index-article-validation-2026-10-28.json`؛ مسیر آرشیوی). بررسی `mget` روی ۹۳۸ بلوک از ۱۰۰ مقاله، صفر مغایرت شناسه، نوع، ترتیب، بخش و hash داشت. یک جست‌وجوی سادهٔ `warfarin` تعداد ۲٬۶۸۷ سند برگرداند: نتیجه (`uptodate-index-validation-2026-10-28.json`؛ مسیر آرشیوی). این عدد نشانهٔ کیفیت یا ارتباط بالینی نیست.

الاستیک هشدار عبور از low disk watermark پیش‌فرض ۸۵٪ را گزارش کرد؛ index آزمایشی تک‌گره سبز بود، اما ظرفیت دیسک و تنظیم watermark باید قبل از ساخت نسخهٔ عملیاتی بررسی شوند. نه قابلیت تداوم پس از crash و checkpoint و نه کارایی یا امنیت تولیدی تأیید نشده است.

## دستورهای اجرا و آزمون

- ممیزی: `python3 docs/search/audit_full_corpus.py --source /home/amir/Documents/UpToDate --report docs/search/uptodate-full-audit-2026-10-28.json --exceptions /home/amir/.local/share/uptodate-search-audit/exceptions-2026-10-28.jsonl --registry /home/amir/.local/share/uptodate-search-audit/registry-2026-10-28.sqlite3`. رجیستری جدید باید قبلاً وجود نداشته باشد؛ وضعیت `incomplete` برای اجرای قطع‌شده باقی می‌ماند.
- آزمون مرورگر شش استثنا: `python3 docs/search/browser_audit.py --source /home/amir/Documents/UpToDate --ids-file /home/amir/.local/share/uptodate-search-audit/missing-topic-ids.txt`؛ فایل شناسه‌ها از استثناهای `missing_topic` تهیه شد.
- ایندکس اصلی: `python3 docs/search/index_lexical_corpus.py --source /home/amir/Documents/UpToDate --registry /home/amir/.local/share/uptodate-search-audit/registry-2026-10-28.sqlite3 --exceptions /home/amir/.local/share/uptodate-search-audit/exceptions-2026-10-28.jsonl --index uptodate-lexical-20261028-v1 --report docs/search/uptodate-lexical-index-2026-10-28.json`. این دستور index جدید می‌خواهد و روی index موجود ادامه نمی‌دهد. رجیستری کنونی پس از افزودن شش استثنا کامل‌تر از زمان اجرای اصلی است؛ اجرای مجدد به نام index جدید نیاز دارد.
- افزودن شش استثنا با `index_missing_topic_fallback.py` و مسیرهای source، registry، exceptions، ids-file، browser-report، index و report انجام شد؛ این دستور مشخصاً به index پایلوت موجود محدود شده است. فایل‌های JSON خروجی در کنار این گزارش هستند.
- `python3 -m unittest discover -s docs/search -p 'test_index_lexical_corpus.py'`: ۲ تست موفق با transport ساختگی، شامل رد نسخهٔ تغییرکرده؛ `PYTHONPATH=backend python3 -m unittest apps.uptodate.test_search_extraction`: ۸ تست موفق. یک fixture ساختگی با Elasticsearch واقعی ثبت و بازیابی شد و index fixture حذف شد. آزمون استخراج کل corpus مقایسهٔ مرورگر برای تمام سندها یا WebView موبایل نیست.

## کارهای باقی‌مانده و شرایط استفاده

این index یک **خط مبنای متنی بلوک‌محور** است. هیچ مدل/tokenizer واقعی، chunk مدل‌محور، `chunk_id` تولیدشده برای کل corpus، embedding، index برداری، رتبه‌بندی hybrid، API یا UI جست‌وجوی هوشمند و benchmark داوری‌شده وجود ندارد. پاراگراف طولانی ممکن است در فاز مدل به چند chunk با شناسه‌های مستقل و paragraph_id مشترک تقسیم شود. نتیجهٔ این مرحله به معنی صحت محتوایی همهٔ جدول‌ها یا امکان ارجاع کامل همهٔ محتوای بصری نیست. hash مقاله هر تغییری در HTML را باعث تغییر شناسه‌های آن نسخه می‌کند؛ بازسازی ایندکس در تغییر snapshot ضروری است. آزمون موبایل واقعی، version mismatch، مجوز پردازش و نمایش محتوا، بستن مسیر دسترسی به متن، سنجش بار و راه‌اندازی امن تولیدی همچنان باز هستند.
